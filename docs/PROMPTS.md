## [머리말] — 모든 단계 공통

너는 **WTW (Watch The World)** 의 한 단계를 구현하는 세션이다.

1. **시작 전에**
   - `git fetch origin main` 후 **`main` 의 최신**에서 작업 브랜치를 시작한다. (옛 버전에서 시작해 수정이 빠진 일이 있었다.)
   - `CLAUDE.md` · `docs/PLAN.md` · `docs/HISTORY.md` 8절을 읽는다. 이 프롬프트와 기획서가 다르면 **이 프롬프트가 우선**, 둘 다 애매하면 기획서의 원칙(3절)을 따른다.
   - 맡은 단계만 한다. 다른 단계의 일은 하지 않는다.
2. **하는 동안**
   - 결정론 규칙(`CLAUDE.md` 9번)을 지킨다.
   - 시뮬(`sim/`)은 Godot 를 모른다. 화면(`game/`)은 스냅샷을 읽기만 한다.
   - 결과를 억지로 유도하는 코드를 쓰지 않는다. 목표에 못 맞추면 그대로 적는다.
   - 기획서와 다르게 해야 하면 멋대로 바꾸지 말고 보고서의 "기획과 다르게 한 것 / 이유"에 적는다.
   - 빠른 테스트는 수 초~1분 안에 끝나게. 느린 테스트(긴 측정)는 따로 묶어 단계 끝에 한 번.
3. **끝낼 때**
   - 모든 빠른 테스트 통과 · 윈도우 실행 파일(zip) 빌드 성공 · 가상 화면 스크린샷으로 화면이 실제로 뜨는지 확인.
   - 보고서 `docs/reports/<단계>.md`:
     1. **쉬운 말 다섯 줄** (개발자가 아닌 사람이 읽는다)
     2. **해 볼 것** — 실행 파일을 받아 무엇을 눌러 보면 되는지 번호 목록
     3. 한 일 · 측정 결과(목표 대비) · 스크린샷
     4. 기획과 다르게 한 것 / 이유
     5. 알려진 문제 · 다음 단계에 넘길 것
   - 자기 브랜치에 커밋·푸시하고 **`main` 으로 가는 PR** 을 만든다. PR 본문 맨 앞에도 쉬운 말 다섯 줄.
   - 윈도우 zip 을 사용자에게 **파일로 보낸다**(파일 보내기 도구가 있으면 그것으로). 윈도우가 처음 실행 때 "PC 보호" 경고를 띄우면 "추가 정보 → 실행"으로 연다는 안내를 붙인다.
   - 사용자에게 하는 마지막 말은 **쉬운 한국어**로, 보고서의 다섯 줄 + 해 볼 것 + PR 링크.

## [E0] 바탕

### 목표
뒤의 모든 단계가 기댈 **뼈대**를 만든다. 행성·사람 같은 실제 내용은 넣지 않는다. 대신 두 가지를 먼저 증명한다:
1. **끊기지 않는 움직임** — 시뮬이 정한 일정을 화면이 매 프레임 부드럽게 따라간다(기획서 6절·17절).
2. **사용자 손에 도착하는 길** — 클라우드에서 만든 윈도우 실행 파일이 사용자에게 가서 실행된다.

### 만들 것

**1. 저장소 구성** (기획서 4절)
```
sim/            Wtw.Sim        — .NET 8 클래스 라이브러리, Godot 참조 없음
sim.tests/      Wtw.Sim.Tests  — xUnit. 빠른 테스트 / 느린 테스트(Trait 로 구분)
tools/bench/    Wtw.Bench      — 측정 도구(콘솔)
tools/*.sh      setup.sh · build.sh · export-windows.sh · screenshot.sh · test.sh
game/           Godot 4.5.1 .NET 프로젝트 (sim 을 프로젝트 참조)
data/           콘텐츠 JSON (지금은 견본만)
Wtw.sln
```

**2. 시뮬 코어 (`sim/`)**
- **결정론 난수**: 빠르고 품질 좋은 생성기(PCG32 나 xoshiro256** 등). 스트림 = (이름 × 지방 번호) 에서 안정 해시로 시드를 뽑는다. 상태를 저장/복원할 수 있어야 한다.
- **안정 해시**: 문자열·숫자 조합 → 64비트. 플랫폼·실행마다 같은 값(`string.GetHashCode` 금지).
- **시간**: 림월드식 틱 시계(기획서 6-1). 1시간 = 2,500틱 · 하루 = 60,000틱 · 1년 40일. 틱 ↔ "○년 ○일 ○시 ○분" 변환·표시 함수.
- **예약 계산기(스케줄러)**: "이 대상은 이 시각에 다시 계산" 을 예약하는 우선순위 큐. 같은 시각이면 **정해진 순서**(예약 순번)로. 예약 취소·당김(급한 일로 끊기) 지원. 하루 경계 훅(지방끼리 주고받기용 자리).
- **세계 껍데기**: 시드 · 시계 · 지방 목록(지금은 빈 것) · 엔티티 저장소(아이디 발급이 결정론적).
- **개입 기록**: 플레이어가 한 일(시각 + 종류 + 값)의 목록. **시작 기록 = 시드 + 설정 + 개입 기록** 이면 세계를 처음부터 똑같이 다시 만들 수 있어야 한다.
- **저장/불러오기**: 버전 번호가 붙은 파일. 저장 → 불러오기 → 계속한 결과가 끊김 없이 계속한 결과와 **비트 단위로 같다**.
- **데이터 읽기**: `data/*.json` 을 읽고 검사(아이디 중복 · 없는 아이디 참조 · 필수 칸)해서, 틀리면 어느 파일 몇 번째 항목이 왜 틀렸는지 쉬운 문장으로 알려 준다. 견본 데이터 두세 개(예: 재료 3개 — 기획서 8-1 의 속성 몇 개를 담아)로 시험. **진짜 데이터는 E4 에서** 만든다.
- **스냅샷**: 화면이 읽을 수 있는 "지금 상태"의 읽기 전용 사본. 시뮬 스레드가 만들고 화면 스레드가 가져간다(이중 버퍼 등, 잠금이 화면을 멈추지 않게).
- **움직임 시험용 대상**: "점" N 개가 지도 위 임의 지점 사이를 걷는다. 각 점은 "출발 시각 · 도착 시각 · 경로(꺾인 선)" 를 정하고 도착 시각에 다음 목적지를 예약한다. (E3 사람의 걷기가 이 구조를 그대로 쓴다.)

**3. Godot 껍데기 (`game/`)**
- 시뮬은 **별도 스레드**. 속도 단계는 기획서 6-2 의 표 그대로, 화면에는 **1배속 ~ 5배속**으로 표시: 일시정지 · 1~3배속(림월드 1배·3배·6배, 1배속 하루 약 16분 40초) · 4배속(하루 3초) · 5배속(하루 0.4초). 키보드: 스페이스 = 일시정지, 1~5 = 속도. (자동 속도는 E0 에서는 만들지 않는다 — 사건이 없으므로.)
- 화면은 스냅샷 + 일정(출발·도착 시각·경로)으로 **매 프레임 보간**해 점을 그린다. 점 500개, 60fps 목표. 시뮬이 바빠도 화면은 끊기지 않는다.
- 화면 위: 날짜(○년 ○일 ○시) · 속도 · 측정값(화면 fps · 시뮬 하루/초).
- 아래 메뉴 막대 자리(림월드식) — 버튼은 저장 · 불러오기 · 새로 시작 정도만.
- **한글 글꼴** 포함(나눔고딕이나 Noto Sans KR 등 OFL 글꼴, 라이선스 파일 같이). UI 테마 바탕(글자 크기 · 색 · 창 모양을 한 곳에서).
- 그림 공급을 한 곳으로 모은다(기획서 17절: 지금은 코드로 그린 원 · 나중에 갈아 끼움).
- 화면 크기: 1920×1080 기준, 창 크기를 바꿔도 깨지지 않게.

**4. 측정 도구 (`tools/bench`)**
- 헤드리스로 "점 N 개 × D 일" 을 돌려 **게임 하루/초**, 메모리, 한 번 계산당 평균 시간을 잰다.
- 결과를 JSON 으로 저장하고 **기준 파일**(`tools/bench/baseline.json`)과 비교해 빨라졌나/느려졌나를 한 줄로 보여 준다.
- 여러 시드를 코어마다 나눠 돌리는 옵션(뒤 단계의 "시드 20개 중앙값" 용).

**5. 테스트 (`sim.tests/`)** — 최소한:
- 같은 시드 → 같은 난수열 / 스트림이 서로 독립 / 새 스트림을 추가해도 기존 스트림 값이 안 바뀜
- 안정 해시가 알려진 값과 같음(값을 테스트에 박아 둠)
- 달력 변환(분 ↔ 년·일·시·분)
- 스케줄러: 같은 시각 순서가 정해져 있음, 취소·당김
- 저장 → 불러오기 → 계속 = 끊김 없이 계속 (비트 단위)
- 시작 기록으로 다시 만든 세계 = 원래 세계
- 데이터 검사가 틀린 데이터를 잡음
- 점이 도착 시각에 정확히 도착하고, 보간 위치가 경로 위에 있음

**6. 빌드와 전달**
- `tools/setup.sh`: 클라우드(우분투)에 .NET 8 SDK · Godot 4.5.1 .NET(리눅스, 헤드리스 실행용) · **윈도우 내보내기 템플릿**을 `.tools/` 에 설치. 이미 있으면 건너뜀. (옛 기록: 이 조합은 클라우드에서 된다고 확인됨.)
- `.claude/settings.json` 에 **SessionStart 훅**으로 `tools/setup.sh` 를 걸어, 뒤 세션들이 자동으로 환경을 갖추게.
- `tools/export-windows.sh`: 윈도우 x86_64 실행 파일을 내보내 `dist/WTW-<단계>-windows.zip` 으로 묶는다(실행에 필요한 .NET 파일 포함, 사용자 PC 에 따로 설치할 것이 없게).
- `tools/screenshot.sh`: 가상 화면(xvfb)에서 게임을 몇 초 돌리고 스크린샷.
- **GitHub Actions CI**: PR 마다 빌드 + 빠른 테스트. 가능하면 윈도우 zip 도 만들어 CI 결과물로 올린다(사용자가 GitHub 에서도 받을 수 있게).

**7. 보고서** `docs/reports/E0.md` ([머리말] 의 형식)

### 다 됐다는 기준
- [ ] 빠른 테스트 전부 통과, CI 초록
- [ ] 점 500개를 5배속으로 돌려도 화면 60fps 근처, 움직임이 뚝뚝 끊기지 않음(1배속에서 특히)
- [ ] 측정: 점 500개 헤드리스 **하루/초** 를 기록하고 기준 파일로 저장 (목표 수치는 없음 — 이 값이 앞으로의 기준)
- [ ] 저장 → 불러오기 → 계속이 같은 결과(테스트) + 게임 화면에서도 됨
- [ ] 한글이 깨지지 않음(스크린샷)
- [ ] 윈도우 zip 이 사용자에게 전달됨 + 해 볼 것 목록
- [ ] PR(→ `main`) 생성

### 해 볼 것 (사용자에게 줄 목록의 바탕)
1. zip 을 풀고 `WTW.exe` 실행 (경고가 뜨면 "추가 정보 → 실행")
2. 점들이 부드럽게 움직이는지 본다
3. 1~5 키로 1배속 ~ 5배속을 바꿔 본다, 스페이스로 멈춘다
4. 저장 → 조금 더 돌림 → 불러오기 → 점들이 저장한 자리로 돌아오는지
5. 위쪽 날짜가 "○년 ○일 ○시" 로 넘어가는지

## [E1] 행성

### 목표
**3D 지구본**으로 행성을 만들고 돌려 볼 수 있게 한다. 아직 사람·지방 지도는 없다(지방 지도는 E2). 기획서 5-1 · 5-2 · 5-5 를 따른다.
이 단계가 끝나면 사용자는 **새 세계를 만들고, 지구본을 돌리고, 칸을 눌러 어떤 땅인지 보고, 지도 모드를 바꿔 볼 수 있다.**

### 만들 것

**1. 측지 육각 격자 (`sim/`)**
- 정이십면체를 나눈 측지 격자(골드버그 다면체). 분할 수 72 → **전체 51,842 칸 = 육각형 51,830 + 오각형 12**.
- 칸마다: 아이디(0부터 차례, 결정론적) · 중심 좌표(단위 구) · 이웃 목록(시계 방향으로 정렬, 육각형 6 · 오각형 5) · 꼭짓점(화면용).
- 격자 자체는 시드와 무관하다 — 한 번 만들어 캐시해도 된다. 만드는 데 걸리는 시간을 측정해 보고.
- 결정론: 좌표를 실수로 계산하더라도 **칸 번호·이웃 순서는 정수 규칙으로** 정해서 기계마다 같게. 지형 생성에 쓰는 실수 계산이 기계마다 다르게 나올 수 있는 곳(삼각함수 등)은 결과를 정수 칸 값(고도 단계 등)으로 바꿔 저장하고, 시뮬은 그 정수만 쓴다.

**2. 행성 만들기**
- 설정(새 세계 화면에서 고름): **시드 · 땅의 양**(16,000 기본 / 20,000 / 24,000 — 같은 행성에서 땅 비율만 바뀜) · **기후 경향**(추움 / 보통 / 따뜻함).
- 땅 칸 수는 고른 값의 ±3% 안에 들어야 한다.
- 모양: **큰 대륙 하나(땅의 70~85%) + 작은 섬 3~8개.** 해안선은 들쭉날쭉하게, 산맥 · 고원 · 평야 · 호수.
- **오각형 12개는 바다에 오도록** 행성을 돌려 놓는다(또는 대륙 위치를 고른다). 땅에 걸리면 몇 개였는지 보고.
- **고도**: 정수 단계(예: 깊은 바다 · 얕은 바다 · 해안 · 평지 · 언덕 · 산 · 높은 산).
- **기후는 지역별 고정**(보이는 계절 없음): 위도 · 고도 · 바다와의 거리 · 바람(위도대별 탁월풍, 산맥 뒤 비그늘)로 **연평균 기온 · 강수량**.
- **생물군계**: 기온 × 강수로 — 얼음 · 툰드라 · 침엽수림 · 온대림 · 초원 · 사막 · 사바나 · 열대우림 · 습지 · 고산 등 10개 안팎.
- **강**: 높은 곳에서 바다·호수로 흐르는 칸 사이 선. 강이 있는 칸 표시.
- **땅속·땅위 자원**(칸 단위, 아직 개수 대신 "있음/많음"): 돌 · 부싯돌 · 진흙 · 구리 · 주석 · 철 · 소금 · 숲 · 사냥감 · 물고기 정도. 지형과 맞게(진흙은 강가, 구리는 언덕·산 …). **E4 의 재료 데이터가 이 이름을 그대로 쓸 수 있게** 아이디를 정해 `data/` 에 둔다.
- 칸마다 **지방 시드**(E2 에서 지방 지도를 만들 때 쓸 값)도 정해 둔다.
- 저장: 행성은 **시드 + 설정으로 다시 만들 수 있으므로 칸 하나하나를 저장하지 않는다.** 저장 파일엔 시드·설정만(+ 나중에 바뀐 칸만). 불러오기 = 다시 만들기 → 같은 행성(지문 테스트).
- 목표 시간: 행성 만들기 **10초 이내**(클라우드 측정값 보고).

**3. 지구본 화면 (`game/`)**
- 행성을 **하나의 메시**로 그린다(칸마다 노드를 만들지 말 것). 칸 색은 정점 색이나 텍스처로, 지도 모드를 바꾸면 색만 다시 칠한다. **60fps** 목표.
- 높낮이: 산은 살짝 솟게(과하지 않게), 바다는 매끈하게. 단순한 빛(해가 한쪽에서)으로 둥근 느낌.
- 조작: **왼쪽 끌기 = 돌리기**(관성 있게, 부드럽게), **휠 = 확대/축소**(부드럽게, 가까이 가면 칸 경계선이 보임), 칸 **누르기 = 고르기**(테두리 강조).
- **칸 정보 창**(오른쪽 또는 아래 한 칸, 기획서 7-6 의 "창끼리 가리지 않게"): 생물군계 · 고도 · 연평균 기온 · 강수 · 강/해안/호수 · 자원 · 좌표(위도·경도) · **왜**(예: "춥다 ← 북쪽 높은 위도 + 산 위", "비가 적다 ← 산맥 뒤 비그늘").
- **지도 모드**(아래 막대의 단추 + 키): 지형(기본) · 생물군계 · 기온 · 강수 · 자원(고른 자원이 있는 칸만 밝게). 세력·인구·교역·기술 모드는 **단추 자리만** 두고 "아직 없음"으로(E7~ 에서 채움). 모드마다 작은 **범례**.
- **새 세계 화면**: 게임을 켜면 먼저 나온다. 시드(직접 입력 / 무작위) · 땅의 양 · 기후 경향 → [만들기]. 만드는 동안 진행 표시.
- E0 의 점 시험 화면은 없애거나 개발용 키로만 남긴다(사용자에게는 지구본이 기본).
- 그리기 방식: E0 에서 고른 "호환(OpenGL)" 으로 지구본이 충분히 예쁘고 빠르면 그대로. 부족하면 바꾸고 이유를 보고서에.

**4. E0 검토에서 넘어온 작은 일**
- **저장 단추 = 멈춘 다음 저장.** 달리는 중에 저장하면 화면보다 앞선 상태가 저장되는 문제(E0 보고서 "알려진 문제") — 멈춰서 화면이 시뮬을 따라잡은 뒤 저장하면 "보이는 것 = 저장된 것".
- **CI 의 윈도우 zip 이름**이 `E0` 로 고정돼 있다 → 단계 이름을 한 곳(예: `game/project.godot` 의 version)에서 읽게.
- **측정 기준 비교**: 기준 파일은 그것을 잰 컴퓨터에서만 의미가 있다(클라우드 컴퓨터마다 ±40% 차이). 기준 파일에 컴퓨터 정보(코어 수 · CPU 이름)를 같이 적고, 다른 컴퓨터면 "느려짐" 대신 "다른 컴퓨터 — 비교 안 함"이라고 알려 주게. 같은 실행 안에서 **기준 코드와 새 코드를 번갈아 재는 방식**도 괜찮다.

**5. 테스트** — 최소한:
- 격자: 칸 51,842 · 오각형 12 · 모든 이웃 관계가 서로 맞음(A 의 이웃에 B 면 B 의 이웃에 A) · 이웃 수 5/6
- 같은 시드 + 설정 → 같은 행성(칸별 값 지문) · 다른 시드 → 다른 행성
- 땅 칸 수가 설정 ±3% · 큰 대륙 비율 70~85% · 섬 3~8개 (시드 20개에서)
- 오각형이 땅에 걸린 시드 수 보고
- 강은 높은 곳 → 낮은 곳으로만 흐르고 바다·호수에서 끝남
- 저장 → 불러오기 → 같은 행성

### 다 됐다는 기준

- [ ] 새 세계 화면 → 행성 만들기 10초 이내(클라우드) → 지구본
- [ ] 지구본 돌리기·확대가 부드럽고 60fps 근처(클라우드 가상 화면 값 + 윈도우에서 확인 부탁)

- [ ] 지도 모드 5개 + 범례
- [ ] 스크린샷: 지형 · 생물군계 · 기온 모드, 칸 정보 창, 새 세계 화면
- [ ] 윈도우 zip 전달 + 해 볼 것 목록, PR(→ `main`)

### 해 볼 것 (사용자에게 줄 목록의 바탕)

## [E2] 지방

### 목표
지구본의 땅 칸을 누르고 들어가면 **그 지방의 2D 지도**가 펼쳐진다. 아직 사람은 없다(E3). 기획서 5-3 · 5-4 · 10절(타일 하나에 오브젝트 하나) · 17절(그림은 코드로)을 따른다.
이 단계가 끝나면 사용자는 **땅 칸으로 들어가 숲·강·바위·광맥이 있는 지방을 둘러보고, 이웃 지방까지 이어 보고, 다시 지구본으로 나올 수 있다.**

### 만들 것

**1. 지방 지도 만들기 (`sim/`)**
- 지방 = 행성의 땅 칸 하나. 지도는 **150×150 네모 칸**이고, 그 안의 **육각형 모양만 쓰는 땅**, 바깥은 쓰지 않음(검게).
  - 육각형의 **여섯 변 = 행성 칸의 여섯 이웃**(E1 의 이웃 순서 = 시계 방향 그대로). 어느 변이 어느 이웃인지 정해 두고 그대로 쓴다.
  - **오각형 칸**(땅이 많을 때 몇 개 생김): 육각형 지도에서 **한 변을 막는다**(그 변은 절벽이나 바다처럼 넘을 수 없게). 이웃 다섯 개는 나머지 다섯 변에.
- **처음 들어갈 때** 칸 정보(지형 · 높이 · 생물군계 · 기온 · 강수 · 강 · 해안/호숫가 · 자원 단계) + `Planet.ProvinceSeed(칸)` 로 만든다. 같은 칸 = 언제나 같은 지도(결정론). 만든 지도는 기억해 두고, **저장 파일에는 지도 전체가 아니라 "바뀐 것"만**(지금은 늘 없음 — 나무를 베는 것 같은 변화는 E3~ 에서) 넣을 수 있는 자리를 만든다.
- 땅 칸(타일)마다: **땅 종류**(흙 · 풀밭 · 모래 · 진흙 · 바위 땅 · 눈 · 얕은 물 · 깊은 물 · 습지 …) + **높이 단계** + 그 위에 **오브젝트 최대 하나**.
- **이웃과 이어지게**: 변을 맞댄 두 지방은 경계에서 자연스럽게 이어져야 한다 — 강은 행성의 강 방향(`Downstream`, 위쪽에서 흘러드는 이웃)과 같은 변으로 들고 나고, 해안 쪽 변은 바다, 산 쪽 변은 높다. 경계의 모양은 **두 칸 번호로 정한 공유 시드**로 만들어, 어느 쪽을 먼저 만들든 같은 경계가 나오게.
- 강: 행성 칸의 강 크기(`RiverSize`)에 맞는 폭으로 지도를 가로지른다. 호숫가 · 해안 칸이면 지도 안에 호수 · 바다가 있다.
- 지형: 칸의 높이 단계에 맞게 — 평야는 대부분 평평, 언덕·산 칸은 바위 땅과 높낮이, 높은 산은 바위와 눈.

**2. 오브젝트** — "**타일 하나에 오브젝트 하나, 다루는 법에 따라 여러 자원**"(기획서 10절)
- 데이터 `data/objects.json`: 오브젝트마다 아이디 · 한국어 이름 · 어떤 생물군계/땅에 나나 · **다루는 법 → 나오는 자원** 목록.
  - 예: 사과나무 — 따기 → 사과 / 베기 → 나무 · 소나무 — 베기 → 나무, 송진 · 덤불 — 따기 → 열매 / 베기 → 잔가지 · 큰 바위 — 깨기 → 돌 · 부싯돌 무더기 — 줍기 → 부싯돌 · 구리 광맥 — 캐기 → 구리 광석 · 진흙 바닥 — 파기 → 진흙 · 갈대 — 베기 → 갈대 · 풀 — 베기 → 풀
  - 생물군계마다 다른 나무·풀(열대우림 · 온대림 · 침엽수림 · 사바나 · 사막 · 툰드라 …). 처음엔 20~30개면 충분.
  - 자원 아이디는 **E1 의 `data/resources.json` 과 같은 이름 체계**. 자원 아이템 자체(사과 · 나무 · 돌 …)의 성질(기획서 8-1 속성)은 **E4 에서** 채운다 — 지금은 아이디와 이름만.
- 칸의 자원 단계(없음/있음/많음)가 지도 안 오브젝트 수를 정한다(구리 "많음"이면 광맥이 더 많이). 숲 칸이면 나무가 빽빽하게.
- 테스트로 데이터 검사(없는 자원 아이디, 겹치는 아이디).

**3. 2D 지방 화면 (`game/`)**
- **들어가기**: 지구본에서 땅 칸을 고르고 칸 정보 창의 **[들어가기]** 를 누르거나 땅 칸을 **두 번 누르면** 2D 로. **나가기**: [지구본으로] 단추 또는 Esc → 들어갔던 칸을 보는 지구본으로 돌아온다.
- 카메라: 끌기 = 이동(E1 의 관성 규칙 그대로 — 멈춘 채 놓으면 서기), 휠 = 확대/축소(부드럽게). 가장 멀리 = 지방 전체가 한 화면, 가장 가까이 = 타일 하나가 화면에서 손가락만 하게(E3 에서 사람을 볼 크기).
- **선택한 곳만 밝게, 나머지는 검게**(기획서 5-4): 밝은 범위는 지금 들어간 지방. 위쪽 단추 **[이 지방만] / [이웃까지]** — "이웃까지"를 누르면 **육각형 지방들을 빈틈없이 이어 붙여** 둘레 이웃(바다가 아닌 칸)까지 밝게 보여 준다. (세력이 생기면 E7 에서 "세력 전체"로 바뀐다.) 밝은 범위 밖은 완전히 검게, 가장자리에 이웃 지방 이름이나 방향만 흐리게.
- 타일이나 오브젝트에 **마우스를 올리면 작은 카드**(이름 · 땅 종류 · 다루는 법 → 자원), **누르면** 같은 칸 정보 창에 자세히(지구본의 칸 정보 창과 같은 자리, 창끼리 가리지 않게).
- 그리기: 한 지방 = 22,500 타일 × (이어 보면 7 지방). **60fps** 를 지키는 방식으로(타일마다 노드 금지 — 한 번에 그리기). 프로그램을 키운 채 여러 지방을 드나들어도 느려지거나 메모리가 계속 늘지 않게.
- 지구본 칸 정보에 이 지방을 열어 봤는지 표시는 하지 않는다(기획서의 "흐릿함 → 열림"은 **사람이 들어가 사는 것**이 기준이라 E3 이후).

**4. 그림 (기획서 17절 — 사용자에게 그림 재료가 없다)**
- 땅과 오브젝트를 **코드로 그린다**: 해상도 높게(확대해도 각지지 않게), 림월드풍 단순 일러스트. 같은 종류도 시드로 조금씩 다르게(나무 크기·기울기·색).
- **타일 격자선이 보이지 않게**: 땅 종류의 경계는 부드럽게 섞는다(지구본에서 칸 선을 없앤 것과 같은 이유 — 보기에 불편함).
- 물은 잔잔하게 움직이는 느낌이면 좋다(과하지 않게, 성능 우선).
- 그림 공급은 E0 의 `Art` 한 곳으로 — 나중에 진짜 그림으로 갈아 끼울 수 있게.

**5. 측정**
- 지방 하나 만들기 시간(목표 **0.5초 이내**, 클라우드) · 지방 하나의 메모리 · 이웃까지 7 지방 만들기 시간.
- 빠른 테스트에는 작은 시드 몇 개, 느린 테스트로 **시드 20개 × 땅 칸 여러 종류**(평야 · 숲 · 산 · 해안 · 강 · 사막 · 툰드라 · 오각형)를 만들어 오브젝트 · 땅 종류 분포를 보고.

**6. 테스트** — 최소한:
- 같은 칸 = 같은 지도(지문), 다른 칸 = 다른 지도
- 육각형 밖 타일은 쓰지 않음 · 오각형 지방은 한 변이 막힘
- **경계가 맞음**: 이웃한 두 지방의 맞댄 변에서 강 · 바다 · 높이가 이어짐(어느 쪽을 먼저 만들어도 같음)
- 강이 행성의 강 방향과 같은 변으로 들고 남
- 칸의 자원 단계와 지도 안 오브젝트 수가 맞는 방향(많음 > 있음 > 없음)
- `data/objects.json` 검사
- 저장 → 불러오기 → 같은 지방(지도는 다시 만들어 같음)

6. Esc 로 지구본으로 나왔다가 같은 칸에 다시 들어가면 같은 지도인지
7. 위쪽 "화면 ○○ fps" 가 60 근처인지

## [E3] 사람

### 목표
빈 지방에 **사람을 뿌리면**, 사람들이 스스로 먹고 · 자고 · 추위를 피하고 · 서로 만나 친해지고 · 짝을 짓고 · 아이를 낳는다. 아직 실험 · 발견(E4), 지식(E5), 건물(E6), 정착 · 정치(E7)는 없다. 기획서 **6절(시간 · 예약) · 7절(사람) · 17절(그림 · 움직임) · 18절(인구와 연산량)** 을 따른다.
이 단계가 끝나면 사용자는 **지방에 사람을 몇 명 뿌리고, 1배속으로 그 사람들의 하루를 지켜보고, 인물 카드로 누가 누구인지 · 왜 그 일을 하는지 볼 수 있다.**

### 만들 것

**1. 사람 뿌리기 (플레이어의 첫 권능)**
- 2D 지방 화면 아래 막대에 **[사람 뿌리기]**: 누르고 땅을 누르면 그 자리에 한 명, **[가족 뿌리기]** 는 2~4명(짝 + 아이). 걸을 수 있는 땅에만.
- 개입 기록(E0)에 남는다 — 시작 기록으로 다시 만들면 같은 사람들이 같은 자리에.
- 뿌린 사람: 나이 15~40 · 이름 · 타고난 능력 · 특성 · 몸이 시드로 정해진다. 아무것도 모른다(지식 없음 — E5).
- 이름: 소리 조각을 이어 만든 짧은 이름(실존 인물과 겹치지 않게, 말이 갈라지는 건 E11).

**2. 시간과 예약 (기획서 6-1)**
- E0 의 예약 계산기 위에서 **사람은 "언제까지 무엇을 한다"를 정하고 다음 판단 시각을 예약**한다. 매 틱 계산하지 않는다(조용한 사람은 비용 0).
- 급한 일(심한 배고픔 · 추위 · 위험 · 누가 말을 걸어옴)만 예약을 끊는다.
- 사람의 하루는 **그 지방의 시각**(E2: 경도에 따라 다름)을 따른다 — 해가 지면 자고, 해가 뜨면 일어난다.

**3. 욕구와 일 (기획서 7-3)**
- 욕구: **배고픔**(하루 세 끼) · **잠** · **추위/더위**(E2 의 지금 기온 — 낮밤 차이 포함) · **쉼** · **어울림**. 굶으면 영양실조 → 죽음.
- 할 수 있는 일(지금은 맨손으로 되는 것만): **따기**(열매 · 사과 · 야자 …) · **줍기**(도토리 · 돌 · 부싯돌 — 아직 쓸 데는 없음, 들고 다니기만) · **물 마시기**(민물 — 강 · 호수 · 웅덩이; 짠물은 못 마심) · **자기** · **쉬기** · **이야기하기** · **걷기/둘러보기** · **추위 피하기**(동굴 · 바위 그늘 · 숲으로).
  - 사냥 · 불 · 도구는 없다(E4~). 그래서 추운 곳에서는 살기 어렵다 — **그게 맞다**(억지로 살리지 말 것).
- 오브젝트에서 딴 것은 줄고, 시간이 지나면 다시 난다(열매가 다시 열림). 바뀐 타일은 E2 의 "바뀐 것" 자리(`ProvinceChanges`)에 쌓여 저장된다.
- **동굴**: 사람이 들어가면 그 둘레의 숨김이 걷힌다(E2 에서 "E3 에서 걷음"으로 넘긴 것). 동굴 안은 밤에 덜 춥고 비바람을 피한다.
- **판단은 "일 단위"**: 지금 가장 급한 욕구 + 특성 · 열정 · 가까운 거리로 일을 고른다. 모든 판단에는 **이유**가 남는다 → 인물 카드의 "지금 하는 일 — 왜"(원칙 1: 모든 것에 "왜").

**4. 길 찾기 · 움직임**
- 걸을 수 있는 타일만(`GroundInfo.IsWalkable` — 바위 · 깊은 물 · 절벽 · 분화구 못 감). 150×150 지도에서 자주 찾아도 느려지지 않게(경로 캐시 · 지역 나누기 등 — 방법은 맡김).
- 걷는 모습은 E0 의 "구간(출발 · 도착 · 경로)" 구조 그대로 → 화면은 매 프레임 보간 — **뚝뚝 끊기지 않게**(원칙).
- 걷기 속도: 1배속에서 림월드 사람과 비슷하게. 특성 "빠른 발" · 다침 · 나이로 달라짐.
- **지방 경계는 아직 넘지 않는다**(여러 지방은 E8). 가장자리에 닿으면 돌아선다. 보고서에 적기.

**5. 능력치 · 기술 · 열정 · 특성 (기획서 7-1 · 7-2 그대로)**
- 타고난 능력 5(힘 · 손재주 · 영리함 · 말재주 · 담력) 1~10, 기술 10(사냥 · 채집 · 농사 · 요리 · 건설 · 제작 · 실험 · 가르치기 · 싸움 · 치료) 0~10. 지금 쓰이는 기술은 채집 · 대화 정도 — 나머지는 자리만, 0 에서 시작.
- **기술 ≠ 지식**(기획서 7-1). 지식(조합식)은 E5.
- **열정 🔥 은 삶에서 얻는다**(기획서 7-1). E3 에서 **시험하고 판단**: 열정이 있는 사람과 없는 사람의 기술 오름 · 기분 차이를 측정해, 뚜렷하지 않거나 계산만 늘면 **없애자고 보고**(사용자가 허락함).
- **특성 22개**(기획서 7-2 표 그대로) — 부가 효과가 실제로 능력치 · 행동에 걸린다. 한 사람 1~3개, 반대끼리는 같이 안 가짐. 타고나거나(부모 영향 조금) 큰 사건으로 생긴다.

**6. 생각 · 기분 · 정신 붕괴 (기획서 7-3)**
- 생각 20개 안팎(배부름 · 굶주림 · 추위 · 잘 잠 · 노숙 · 친구와 이야기 · 짝과 함께 · 가족의 죽음 · 아이가 태어남 · 혼자 너무 오래 …). 사건이 남기고 시간이 지나면 사라진다 → 기분.
- 기분이 낮으면 정신 붕괴(울며 헤매기 · 화풀이(말다툼) · 혼자 떠나기 등 — 싸움 · 피는 아직 아님).
- 목표(기획서 20절): 기분 중앙값 40~55, 정신 붕괴는 한 사람당 1년에 1번 이하. 못 맞추면 그대로 보고.

**7. 관계 · 짝 · 출산 · 죽음 (기획서 7-4)**
- 호감 + 원한 + 은혜. 이야기하면 호감이 오르내림(말재주 · 특성 영향).
- 혼자 사는 사람 → 만남 → 짝 → 아이. 아기 · 아이는 어른을 따라다니고 자란다. 부모를 닮는다(몸 · 능력 조금 · 특성 조금).
- 죽음: 굶주림 · 추위 · 늙음 · 병(아주 간단히 — 자세한 병은 나중). 시신은 그 자리에(무덤은 E6).
- 가족 · 친구가 죽으면 생각이 남는다.

**8. 그림 — 절차적 몸 (기획서 7-5 · 17절)**
- 사람을 **코드로 그린다**: 몸 · 머리 · 얼굴 · 머리카락 · (아직 옷 없음 — 맨몸 대신 단순한 가죽 두름 정도) 를 부품별로 겹쳐서. **정면 · 옆 · 뒤 세 방향**. 체형 · 피부 · 머리카락 색이 사람마다.
- 해상도 높게, 림월드풍. 걷기 흔들림 · 방향 전환 · 앉기/눕기(잘 때) 같은 작은 움직임은 위치 · 기울기 · 크기만 바꿔도 부드럽게.
- 그림 공급은 `Art` 한 곳으로(나중에 진짜 그림으로 갈아 끼울 수 있게).

**9. 인물 카드 (기획서 7-6)**
- 사람에 **마우스를 올리면 작은 카드**(얼굴 · 이름 · 나이 · 지금 하는 일 · 기분).
- **누르면 큰 카드**, 슬롯(탭) 7개: ① 개요(얼굴 · 이름 · 나이 · 지금 하는 일과 **왜** · 기분) ② 능력(능력 5 · 기술 10 · 열정 · 특성 — 특성에 마우스를 올리면 효과) ③ 몸(건강 · 다침 · 욕구 막대) ④ 마음(기분과 원인 = 생각 목록) ⑤ 관계(가족 · 짝 · 친구 · 원한) ⑥ 지식(지금은 "아직 아는 것이 없다") ⑦ 이야기(이 사람의 전기 — 태어남 · 뿌려짐 · 짝을 만남 · 아이 · 죽음 같은 큰 일들, **문장은 틀 + 조각**, AI 문장 금지).
- 큰 카드는 한 번에 하나, 다른 창과 겹치지 않게. 카드에서 **[따라가기]** → 카메라가 그 사람을 따라감.
- 지방 화면에 **사람 목록**(이름 · 나이 · 지금 하는 일, 누르면 그 사람으로).

**10. 화면 · 지구본**
- 2D 지방 화면에 사람이 보인다. 1배속에서 지켜볼 만한 크기 · 속도.
- **지구본**: 사람이 있는 칸은 표시(작은 사람 표시 + 인원). 기획서 5-2 의 "아무도 살지 않은 칸은 흐릿하고 들어가 살면 열린다" — 사람이 사는 칸을 "열린 칸"으로 밝게, 아직 아무도 산 적 없는 칸은 지금보다 살짝 흐릿하게(지형은 보이게, 과하지 않게).
- 알림: 아이가 태어남 · 누가 죽음 · 짝이 됨 · 정신 붕괴(누르면 그 사람으로).

**11. E2 에서 넘어온 작은 일**
- **지방 정보 칸이 길다**(19항목마다 "자세히 보기" 줄) → 항목 줄을 누르면 그 항목의 이유가 펼쳐지게 하고, 따로 있는 "자세히 보기" 줄은 없애 길이를 반으로. 자주 보는 항목(시각 · 기온 · 물 · 자원)을 위로.
- "공기: 축축함"과 "강수: 아주 건조"가 한 지방에서 같이 나와 서로 어긋나 보인다 → 이름이나 기준을 사람이 읽기에 어긋나지 않게.

**12. 측정 — 이 단계에서 꼭 결정할 것 두 가지**
- **사람 상한 확정**(기획서 18절): 헤드리스로 사람 300명 · 500명을 넣고 100년(4,000일) — 한 시드 걸린 시간 · 사람 하루당 비용 · 메모리. **500명 100년 ≤ 2분이면 상한 500 유지**, 아니면 낮추자고 보고. (실제 인구는 식량으로 멈춰야 함 — 상한은 안전장치)
- **열정 유지/삭제**(위 5번).
- 그 밖에: 시드 20개 × 사람 10명 뿌림 × 50년 → 인구 변화 · 죽음 원인 비율 · 기분 중앙값 · 정신 붕괴 빈도 · 짝 · 출산 수. 목표에 못 맞추면 그대로 보고(억지 금지). 1배속 화면 fps.

**13. 테스트** — 최소한:
- 같은 시드 + 같은 뿌리기 기록 → 같은 사람 · 같은 결과(지문)
- 저장 → 불러오기 → 계속 = 끊김 없이 계속(사람 · 관계 · 생각 · 예약 · 바뀐 타일 포함)
- 길 찾기: 바위 · 물을 지나가지 않음, 갈 수 없는 곳은 포기
- 굶으면 죽고, 먹으면 살고, 짠물은 마시지 않음
- 해가 지면 잔다(지방 시각 기준)
- 특성 효과가 능력치에 걸림 · 반대 특성은 같이 없음
- 아이는 부모를 닮음(몸 · 능력의 방향)
- 빠른 테스트는 1분 안(무거운 건 느린 테스트로)

### 해 볼 것 (사용자에게 줄 목록의 바탕)
1. 새 세계 → 따뜻하고 열매가 많은 땅(숲 · 초원, 강가)으로 들어가기
2. [가족 뿌리기]로 두세 가족, [사람 뿌리기]로 혼자 사는 사람 몇
3. 1배속으로 지켜보기 — 걷는 모습이 부드러운지, 무엇을 하는지
4. 사람에 마우스를 올려 작은 카드, 눌러서 큰 카드의 슬롯들 — 특히 "지금 하는 일 — 왜"
5. [따라가기]로 한 사람을 따라가 하루를 본다(밤에 자는지)
6. 4~5배속으로 몇 년 돌려 짝 · 아이 · 죽음 알림이 오는지
7. 추운 땅(툰드라)에 뿌리면 어떻게 되는지
8. 지구본으로 나와 사람 사는 칸이 표시되는지
9. 위쪽 "화면 ○○ fps"(사람이 많을 때)

## [E3b] 지방 넘기

### 목표
사람이 **지방 경계를 걸어서 넘어** 이웃 지방으로 간다. 물 · 먹을 것이 없거나 모자라면 옮겨 가고, 그렇게 **사람들이 행성 위로 퍼져 나가기 시작한다.** 떨어져 사는 무리끼리는 말이 조금씩 달라지고(사투리의 시작), 사람들이 땅에 이름을 붙인다. 기획서 **5-4 · 5-5 · 14-1(언어) · 18절**을 따른다. (먼 여정 · 유목 무리 · 국경 · 지방마다 CPU 는 E8.)
이 단계가 끝나면 사용자는 **사람을 뿌리고 빠르게 돌려, 무리가 물과 먹을 것을 찾아 옆 지방으로 퍼져 나가고, 지구본에서 사람 사는 칸이 늘어나며, 땅에 이름이 붙고, 말이 갈라지기 시작하는 것을 볼 수 있다.**

### 만들 것

**1. 지방 안의 작은 물 (가장 먼저 — E3 검토에서 드러난 큰 문제)**
- 지금은 지방의 물이 행성의 강 · 호수 · 바다에서만 와서, **아무 땅이나 고르면 100곳 중 90곳에 마실 민물이 없다**(열대우림 · 온대림까지 — `docs/reports/E3/measure-nosource.md`). 비가 오는 땅이면 작은 물이 있어야 한다.
- 지방 지도에 **개울 · 샘 · 웅덩이(빗물 고임) · 늪**을 강수 · 지형 · 땅에 맞게 만든다: 비가 많으면 개울이 여럿, 보통이면 샘 · 웅덩이 몇, 사막은 드물게(오아시스), 얼음 땅은 녹은 물 웅덩이(추워서 마시기 어려움은 그대로). 개울은 낮은 쪽으로 흐르고, **이웃 지방과 경계에서 이어지게**(E2 의 "타일을 행성 위의 점에 놓는" 방법으로).
- 이건 E2 의 지방 지도 만들기를 바꾸는 일이라 **지방 지도 지문 고정값 테스트가 바뀐다** — 일부러 고치고 보고서에 적는다.
- 측정 목표: 생물군계별 "마실 민물이 있는 지방" 비율 — 습한 곳(열대우림 · 온대림 · 침엽수림 · 습지)은 **90% 이상**, 초원 · 사바나 · 툰드라는 절반 이상, 사막 · 고산은 낮게. 못 맞추면 그대로 보고.

**2. 경계 넘기**
- 사람이 지방 가장자리(육각형의 변)를 걸어서 **이웃 지방으로 넘어간다.** 바다 · 절벽 · 오각형의 막힌 변은 못 넘는다.
- 넘어가는 지방이 아직 없으면 **그때 만들어지고**(E2 와 같은 지도), 사람이 있는 동안 **자세히 계산**된다(기획서 5-5). 사람이 모두 떠나면 그 지방은 **멈춤** — 다시 사람이 오면 **흐른 시간만큼 한 번에 맞춘다**(딴 열매가 다시 열림 등).
- 길 찾기는 경계를 넘을 수 있어야 한다(이웃 지방 좌표로 이어서 — E2 의 `ProvinceLayout`). 너무 비싸지 않게(경계까지 / 경계부터 나눠 찾기 등 — 방법은 맡김).
- **결정론**: 경계를 넘는 일은 "지방 사이 넘겨주기"로 처리해서, 순서가 언제나 같게. **E8 에서 지방마다 CPU 로 나눌 수 있게** 지방끼리 주고받는 것을 정해진 시각에 묶는 구조로(기획서 5-5 는 하루 경계였지만, 걷는 사람을 하루 동안 세워 둘 수는 없으니 더 짧은 간격 — 예: 1시간 — 으로 묶는 것을 허용; 간격과 이유를 보고서에 적기).
- 저장 · 불러오기: 넘어가는 도중에 저장해도 같은 결과.

**3. 왜 옮겨 가나 — "왜"가 행동과 맞게**
- 사람은 **본 것만 안다**(E3 그대로). 경계 너머도 눈에 보이는 거리만큼은 본다.
- 옮기는 까닭: 지방 안에 물 · 먹을 것이 **없거나**, 사람이 늘어 **모자라거나**(딴 몫이 빨리 줄어듦), 호기심 · 떠나기(정신 붕괴) · 짝을 찾아 · 따라가기. 물을 찾을 때는 낮은 쪽 · 개울이 흘러가는 쪽으로.
- **함께 옮긴다**: 가족 · 짝 · 아이는 같이 간다. 한 무리가 모자라면 일부가 떨어져 나가 새 땅으로 갈 수 있다(이게 나중의 "무리가 갈라짐").
- 카드의 "지금 하는 일 — 왜"에 그대로: "물이 없어 낮은 쪽, 이웃 땅으로 가는 중" 같은.
- 무작정 멀리 가서 죽는 일이 너무 많지 않게 — 돌아오기(아는 물가로)도 판단에 넣는다. 억지로 살리지는 말 것.

**4. 화면**
- 2D: [따라가기] 하던 사람이 경계를 넘으면 **카메라가 따라 이웃 지방으로** 들어간다(밝은 범위도 그 지방으로). [이웃까지]에서는 이웃 지방의 사람도 보인다. 경계를 넘어 사라지는 사람에는 E2 기획대로 가장자리에 "○○가 국경을 넘어감" 표시가 잠깐(조사는 받침에 맞게).
- 지구본: 사람 사는 칸 표시(E3) + **옮겨 가는 무리의 방향**을 작은 화살표나 선으로. 사람 사는 칸이 늘어나는 게 보이게. 사람 목록 · 알림에 지방 이름.

**5. 언어 — 사투리의 시작과 지명 (기획서 14-1 의 E3b 범위만)**
- **갈라짐**: 같은 말을 쓰는 사람들이 서로 오래 이야기하지 않으면(떨어져 삶) 그 무리의 말이 조금씩 바뀐다(소리 무게가 천천히 흘러감, 낱말 소리가 바뀜). 오래 떨어져 바뀐 만큼 **새 말(사투리)로 갈라진다**(E3 의 `Parent` 자리 사용). 다시 만나 함께 살면 다시 닮아 간다.
- **목표 숫자**(기획서 14-1): 떨어져 산 지 약 200년이면 알아듣기 60~85%(사투리), 약 500년이면 40% 아래(다른 언어). 이 단계에서 **측정해서 보고**(목표에 맞게 숫자를 고르되, 못 맞추면 그대로).
- **지명**: 사람들이 한 지방에 오래 머물거나 그 땅의 눈에 띄는 것(큰 강 · 화산 · 바다 · 동굴 · 사건)을 보면 **자기 말로 지방에 이름을 붙인다**(뜻과 함께, 예: "타레 — 붉은 강"). 다른 말을 쓰는 무리는 같은 땅을 다르게 부를 수 있다 — 지금은 "그 땅에 처음 이름을 붙인 무리의 이름"을 보이고, 다른 이름은 칸 정보에 같이 적는다. 지방 이름이 생기면 지방 정보 칸 · 지구본 칸 정보 · 사람 목록 · 알림에 "칸 42331" 대신 그 이름(뜻도).
- **지구본 [언어] 지도 모드**(E1 에서 자리만 있던 모드 중 하나로, 또는 새 단추): 사람 사는 칸을 그 칸 사람들의 말로 칠한다 — 비슷한 말은 비슷한 색(사투리는 같은 색의 옅고 짙음). 한 칸을 누르면 "이 말이 어디까지 통하나"(밝을수록 잘 통함).
- 하지 않는 것(나중): 새 낱말 · 빌려 오기 · 별명(E4~), 성 · 나라 안 사투리(E7), 통역(E9), 글 · 가계도(E11).

**6. 측정**
- 작은 물: 생물군계별 마실 민물이 있는 지방 비율(위 목표).
- **아무 땅에나 뿌림**(E3 의 `measure-nosource` 와 같은 조건 — 시드 20 × 5곳 × 5명 × 3년): "물이 없어 죽은 사람" 비율이 E3(48%)보다 얼마나 줄었나, 옮겨 가서 산 사람 수.
- **퍼져 나가기**: 시드 20 × 따뜻한 땅에 10명 × 100년 — 사람 사는 지방 수 · 가장 멀리 간 거리(칸) · 인구 · 죽음 원인 · 말(사투리) 수와 알아듣기 % 의 변화.
- 속도: 사람 300명이 여러 지방(예: 10~30곳)에 흩어져 100년 — 한 시드 시간 · 사람 하루당 비용 · 메모리(지방이 많이 열려도 메모리가 끝없이 늘지 않게). E8 의 "지방마다 CPU"를 위해 지방끼리 주고받는 양도 보고.

**7. 테스트** — 최소한:
- 같은 시드 + 같은 뿌리기 → 같은 결과(경계를 여러 번 넘어도, 지문)
- 경계를 넘는 도중 저장 → 불러오기 → 계속 = 끊김 없이 계속
- 바다 · 절벽 · 막힌 변은 못 넘음
- 멈춘 지방에 다시 들어가면 흐른 시간만큼 맞춰짐(열매가 다시 열림)
- 개울이 경계에서 이어짐, 습한 지방은 민물이 있음
- 오래 떨어진 무리는 말이 갈라지고, 다시 함께 살면 닮아 감
- 지명이 그 무리의 말로 붙고 조사가 맞음
- 빠른 테스트는 1분 안(무거운 건 느린 테스트로)

## [E4] 재료와 발견

### 목표
사람들이 **스스로 재료를 실험해서** 불 · 석기 · 끈 · 토기 · (운이 좋으면) 구리를 **발견하고 쓴다.** 성공뿐 아니라 **부분 성공도 기억**해 다음 실험의 단서로 삼는다. 먹을 것이 한정되어 **인구가 식량으로 멈추는** "굶주린 세계"도 이 단계에서. 기획서 **8절(재료와 발견) · 14-1(언어 — E4 범위) · 20절(측정)** 을 따른다.
- **하지 않는 것**: 가르치기 · 잊기 · 기록 · 끊김과 되찾음(E5 지식), 집 · 작업대 같은 건물(E6), 동물 · 사냥 · 농사(다음 단계로 따로 — 기획 세션이 정함). 지금 있는 것(땅 위 돌 · 나무 · 풀 · 열매 · 진흙 · 바위 · 광맥)만으로 갈 수 있는 데까지.

이 단계가 끝나면 사용자는 **사람들이 추위와 배고픔 때문에 이것저것 해 보다가 첫 불을 피우고, 돌을 깨 날을 만들고, 진흙을 구워 토기를 만드는 장면을 지켜보고, 발견 목록에서 "누가 · 언제 · 왜 · 어떻게" 를 볼 수 있다.**

### 만들 것

**1. 재료의 속성 데이터 (기획서 8-1)**
- `data/items.json` 의 아이템(지금 30개)과 새로 생길 아이템에 **속성 세기(0~5)** 를 채운다: 탄다 · 녹는다(+ 녹는 불 세기) · 구우면 굳는다 · 되살아난다(광석 → 금속) · 단단함 · 질김 · 쪼개진다 · 휜다 · 펴진다 · 뜯긴다 · 날이 선다 · 무게 · 물에 무른다(빚기) · 물을 막는다 · 썩는다 · 마른다 · 섞인다 · 끈적인다 · 실이 된다 · 먹을 수 있다(+ 영양) · 독 · 따뜻하다. E2 에서 돌마다 적어 둔 성질(낮음/보통/높음)을 숫자로 옮긴다. 필요한 속성은 추측해서 더해도 된다(사용자 허락 — 보고서에 적기).
- **새 아이템(만들어지는 것) 30~40개 안팎, 선사 ~ 구리까지**: 예) 불씨 · 모닥불 · 숯 · 재 · 깬 돌 날 · 찍개 · 긁개 · 돌칼 · 갈아 만든 돌 · 손잡이 단 돌도끼 · 나무 막대 · 뾰족한 막대(불에 그을린) · 끈(풀 · 껍질 꼬기) · 엮은 바구니 · 빚은 진흙 그릇 · 마른 그릇 · 구운 토기 · 익힌 열매/버섯 · 말린 열매 · 돌 화덕(불 가두기) · 구리 광석 덩이 · 녹은 구리 · 구리 덩이 · 구리 날 … (고르는 건 맡김, `data/` 에 한국어 이름 + 영어 아이디).

**2. 다루는 행동과 판정 (기획서 8-2)**
- 행동: 두드리기 · 깨뜨리기 · 갈기 · 자르기 · 뜯기 · 꼬기 · 엮기 · 빚기 · 말리기 · 굽기 · 태우기 · 녹이기 · 섞기 · 담그기 · 끓이기(그릇이 생긴 뒤) · 묻어 두기.
- **판정 = 재료의 속성 × 행동 × 조건**. 가장 중요한 조건은 **불의 세기** 사다리: 불 없음 < 맨불(모닥불) < **불을 가둔 것**(돌 화덕 · 구덩이) < 숯 + 가둔 불 < (나중) 바람 넣기. 손재주 · 쓰는 도구 · 걸린 시간도.
- **조합식을 미리 정답표로 두지 말 것** — 결과는 속성에서 나온다(예: "쪼개짐 높음 + 날 섬 높음 + 두드리기 → 날카로운 조각"). 데이터는 "어떤 속성 조합 + 행동 + 조건이면 어떤 결과 아이템"의 규칙으로.
- **부분 성공**: "붉게 달아올랐지만 녹지 않았다"(불이 모자람) · "금이 갔다"(덜 마름) · "날이 섰지만 곧 부서졌다"(질김 낮음) 같은 결과도 남는다 → 다음 실험이 그 단서를 따라간다(불을 더 세게 · 더 말려서 …).

**3. 실험은 왜 하나 (기획서 8-3) — 필요가 실험을 끈다**
- 욕구 · 사건이 **"~가 있었으면" 바람**을 남긴다: 추워서 떨었다 → 따뜻함 · 날 열매가 배탈 → 익히기 · 딱딱한 것을 못 깬다 → 날카로움 · 물을 나를 수 없다 → 그릇 · 바위를 못 캔다 → 단단한 도구 …
- 바람이 있으면 사람은 들고 있는 것 · 주변에 보이는 것으로 **그 바람에 맞을 것 같은 실험**을 고른다(속성으로 짐작 — 따뜻함이면 "탄다"가 높은 것). 특성 **호기심**은 바람 없이도 실험, **고지식함**은 잘 안 함. 영리함 · 손재주가 성공률에.
- 실험 · 만들기는 **사람의 일**(E3 의 예약 · "왜" 그대로): 카드에 "추워서 — 마른 풀과 부싯돌을 두드려 보는 중", 결과는 생각(기분)과 이야기(전기)에.
- **자연의 사건도 단서**: 화산 둘레의 불 · 마른 땅의 들불 · 번개(드물게) — 불을 "본" 사람이 불을 얻거나 옮겨 올 수 있다(꺼지지 않게 지키기). (플레이어의 권능은 E10.)

**4. 발견한 것을 쓴다**
- 불: 쬐기(추위 피하기 — **툰드라에서 첫날 밤에 모두 얼어 죽던 것이 바뀌어야 한다**), 익히기(배탈 줄고 영양 오름), 밤에 짐승 대신 어둠이 덜 무서움(담력), 땔감 모으기 · 불 지키기. 모닥불은 땅 위에 놓이는 것(타일에 놓임, 시간이 지나면 꺼짐, 비에 꺼짐).
- 석기: 자르기 · 긁기 · 깨기가 빨라짐, **돌 도구가 있으면 바위 타일을 캘 수 있다**(E2 의 "바위는 캐려면 도구" — 캐면 돌이 나오고 숨은 바위 속 · 광맥이 드러남).
- 끈 · 바구니: 더 많이 나르기(열매를 모아 두기), 손잡이 달기.
- 토기: 물을 담아 나르기(물가에서 먼 곳에서도 살기), 모아 두기, 끓이기.
- 구리: 불을 가두고 숯을 쓰는 데까지 가야 녹는다 — **잘 안 나오는 게 맞다**(구리 광맥이 있는 지방에서만, 오래 걸려서).
- 만든 물건은 들고 다니고(무게 한도), 내려놓을 수 있고, 닳는다. 사람이 죽으면 그 자리에 남는다.

**5. 아는 것은 그 사람의 머릿속에 (E5 의 바탕만)**
- 발견한 사람은 그 조합을 안다 — 인물 카드 **[지식] 슬롯**에 "아는 것"(무엇을 · 언제 · 왜 · 어떻게, 부분 성공의 단서도).
- **곁에서 본 사람은 따라 할 수 있다**(그 자리에서 본 경우만, 간단히). 가르치기 · 잊기 · 기록 · 마지막 장인 · 끊김과 되찾음은 E5 — **지금은 아는 사람이 다 죽으면 그냥 사라진다**(되찾음은 다시 발견해야). 보고서에 "사라진 발견" 수를 적기.

**6. 굶주린 세계 (기획서 20절)**
- 지금은 지방 하나가 하루 50~160명분을 먹여 100년 안에 식량으로 멈추는 곳이 적다. 열매가 다시 열리는 빠르기 · 양을 조정해 **사람이 늘면 먹을 것이 모자라고, 모자라면 떠나거나(E3b) 굶는** 세계로. 목표: 굶주림 사망 10~20%, 100년 뒤 인구가 식량으로 멈춤, 멸종 3/20 이하. 못 맞추면 그대로 보고(억지 금지).
- 익히기 · 말려 두기 · 그릇에 모아 두기가 먹을 것을 늘리는 쪽으로 효과가 있어야 발견이 의미 있다.

**7. 언어 — E4 범위 (기획서 14-1)**
- **새로 알게 된 것에 새 낱말**: 발견한 무리의 말로 그 물건 · 일의 낱말이 생긴다(불 · 토기 · 구리 …). 카드 · 발견 목록 · 말풍선에.
- **낱말 빌려 오기**: 다른 말을 쓰는 사람에게서 물건이나 하는 법을 보고 배우면 그 낱말도 따라온다 — 낱말마다 "어디서 왔나"를 기록(나중의 사전 · "지식의 행방").
- **별명**: 큰 일을 한 사람에게 사건이 이름을 붙여 준다(예: "불을 처음 피운 …") — 그 무리의 말로, 뜻과 함께.
- 하지 않는 것: 말이 다르면 가르치기가 느려짐(E5), 사전 창 · 가계도(E11).

**8. 화면**
- 모닥불 · 화덕 · 만든 물건 · 드는 도구가 보이게(코드로 그린 그림, `Art` 한 곳). 불빛은 밤에 둘레를 밝힌다(E2 의 밤 밝기 위에).
- **발견 목록 창**(아래 막대에 [발견]): 이 세계에서 처음 나온 것들 — 무엇 · 누가 · 언제 · 어디서 · **왜**(어떤 바람에서) · 그 전의 부분 성공들 · 지금 아는 사람 수 · 그 말의 낱말. 누르면 그 사람 · 그 땅으로.
- 알림: 첫 발견(세계 처음 / 그 무리 처음), 발견이 사라짐(아는 사람이 다 죽음).
- 인물 카드 [지식] 슬롯 · [이야기]에 발견과 실험.

**9. E3b 에서 넘어온 작은 일**
- [따라가기]로 경계를 넘으면 화면이 60° 단위로 돌 수 있다 → **넘어가도 화면 방향이 그대로**(북쪽이 계속 위)이게.
- 지구본 칸 정보의 "통하는 곳" 목록이 길고 같은 이름이 겹쳐 나온다(예: "잘릭타(큰 나무)" 두 번) → 겹침을 고치고, 목록 대신 "통하는 칸 n곳(지도에서 밝게)" 처럼 줄이기.
- [언어] 지도 모드에서 사람이 안 사는 땅이 모두 같은 회색이라 땅 모양이 안 보인다 → 아래에 옅은 지형을 깔기.
- **그래픽 카드를 너무 많이 쓴다**(사용자 PC 에서 60%): 2D 땅 셰이더가 화면 점 하나마다 그림을 60번쯤 읽고(둘레 타일 9개 섞기 · 무늬 · 높이 16곳), 거의 안 바뀌는 땅을 **매 화면 처음부터** 다시 그린다. 멈춤일 때도 똑같이 그린다.
  1. **땅을 한 번만 그려 두기**: 지방에 들어갈 때(또는 처음 보일 때) 땅 그림을 텍스처로 구워 두고 그 위에는 **물결 · 낮밤 밝기 · 불빛만** 가볍게 덧칠. 땅이 바뀌면(바위를 캠 · 바뀐 타일) **그 부분만** 다시 굽기. 확대해도 각지지 않게 해상도는 적당히(가까이 볼 때만 자세한 조각을 쓰는 식 등 — 방법은 맡김). 지금과 **보기에 거의 같아야** 한다(스크린샷 비교).
  2. **움직이는 게 없으면 덜 그리기**: 멈춤 · 창이 뒤에 있음 · 화면이 안 바뀌는 동안은 초당 몇 번만.
  - 측정: 같은 장면(지방 하나 · 사람 수십 명 · 1배속 / 멈춤)에서 **고친 전후의 화면 한 장 그리는 시간**(클라우드에서 잴 수 있는 값)과, 사용자에게 윈도우 작업 관리자의 GPU % 를 확인해 달라는 안내를 "해 볼 것"에.

**10. 측정**
- **발견 목표**(기획서 20절 — 사람 100~150명 기준, 옛 v2 수치): 모닥불 ~20년 · 토기 ~80년 · 구리 ~150년 (밭은 농사 단계라 제외). 시드 20 × 따뜻한 땅 10명 × 200년: 발견마다 처음 나온 해(중앙값) · 나오지 않은 시드 수 · 사라졌다 다시 나온 수.
- 툰드라 · 추운 땅에 뿌린 사람의 생존(불이 생긴 뒤 바뀌었나).
- 굶주린 세계: 인구 곡선 · 죽음 원인(굶주림 10~20%) · 멸종 수.
- 속도: 사람 300명 · 100년 · 사람 하루당 비용(E3b 245µs 에서 얼마나).

**11. 테스트** — 최소한:
- 같은 시드 → 같은 실험 · 같은 발견(지문)
- 판정이 속성에서 나온다(정답표가 아님): 속성을 바꾸면 결과가 바뀜

## [E5] 지식

### 목표
**지식은 사람 머릿속에 있다** — 가르치고, 배우고, 잊고, 그림으로 남기고, 마지막으로 아는 사람이 죽으면 끊기고, 이웃을 보거나 남은 그림을 보고 되찾는다. 기획서 **9절(지식) · 2절 핵심 경험 3("지식의 행방") · 14-1(언어 — 말이 다르면 가르치기가 느려짐)** 을 따른다. E4 에서 만든 "아는 것 · 곁에서 보고 배움 · 발견이 사라짐"이 바탕이다.
- **하지 않는 것**: 글자(그림 → 뜻 글자 → 소리 글자는 나중에 따로 판단), 동물 · 농사(E5b), 건물(E6), 정치(E7).

이 단계가 끝나면 사용자는 **불 피우는 법이 어느 무리의 누구 머릿속에 있는지 보고, 마지막 장인이 죽어 기술이 끊겼다가 이웃이나 동굴 그림을 보고 되찾는 이야기를 지켜볼 수 있다.**

### 만들 것

**1. 가르치기 · 배우기**
- 아는 사람이 **일부러 가르친다**: 가족 · 무리 안에서, 특히 아이에게. 가르치는 사람의 말재주 · 기술(가르치기), 배우는 사람의 영리함 · 나이(아이가 빨리 배움)로 빠르기가 정해진다. 한 번에 다 배우지 않고 **조금씩 쌓인다**(배우는 중 0~100%).
- **보고 따라 하기**(E4 의 "곁에서 봄")는 그대로 — 가르치기보다 느리고 덜 정확하다.
- **말이 다르면 가르치기가 느려진다**(기획서 14-1: 막지 않고 느리게). 알아듣기 % 에 따라. 보고 따라 하기는 말과 상관없다.
- 왜 가르치나: 아이가 자라서 · 무리에 그 기술을 아는 사람이 적어서 · 바람(필요)이 있는 사람이 물어서. 카드의 "왜"에.
- 기술(솜씨, 0~10)과 지식(아는 법)은 다르다(기획서 7-1): 배웠다고 바로 잘하지는 않는다.

**2. 잊기와 숙련**
- 오래 안 쓰면 **흐려진다**(아는 정도가 줄어 실패가 잦아짐, 아주 오래면 잊음). 자주 쓰면 굳는다. 늙으면 조금씩 잊는다.
- 흐려진 사람도 다시 쓰거나 남에게 배우면 되살아난다.

**3. 그림으로 남기기 (기록 매체의 첫 단계)**
- **동굴 벽 · 바위 면 · 나무껍질 등에 그림**을 그려 아는 법을 남길 수 있다(글자는 아직 없음 — 그림이라 **말과 상관없이** 누구나 조금은 알아본다). 매체마다 오래가는 정도가 다르다(동굴 벽은 오래 · 나무껍질은 금방 썩음).
- 그림을 본 사람은 그 법을 **조금 배운다**(가르치기보다 훨씬 느림, 단서를 얻는 정도일 수도). 그래서 **아는 사람이 다 죽어도 그림이 남아 있으면 되찾을 길이 있다.**
- 왜 그리나: 중요한 걸 잊을까 봐(나이 든 장인) · 큰 발견을 한 뒤 · 무리에 아는 사람이 하나뿐일 때. 처음 그림 그리기도 하나의 **발견**(E4 의 규칙 체계로, 재료: 숯 · 흙 · 재 등)으로 나오면 좋다.
- 2D 지도에 그림이 보이고(코드로 그린 단순한 그림), 누르면 "무엇을 그린 것 같은지 · 누가 · 언제".

**4. 끊김과 되찾음 — "지식의 행방"**
- **무리(함께 사는 사람들) 단위로도** 센다: "이 무리에서 아는 사람이 모두 죽음" = 그 무리에서 끊김(세계에서는 다른 무리가 알 수 있음). 기획서: 기술 손실은 세계에서 사라짐 + **집단 단위 끊김**.
- 되찾는 길: 이웃 무리를 보고 배움 · 남은 그림 · 다시 발견(E4). 어느 길로 되찾았는지 기록.
- 무리는 지금 정식 집단이 없으니(E7) "같은 지방에서 함께 사는 사람들" 정도로 간단히 — E7 이 바꿀 수 있게.

**5. 백과 — "지식의 행방" 창** (E4 의 [발견] 창을 키워서)
- 발견마다: **지금 누가 아나**(사람 · 무리 · 아는 정도), **어디에 남았나**(그림 · 위치), **처음 나온 까닭**(어떤 바람 · 누가 · 언제), **잃음과 되찾음의 역사**(언제 어디서 끊기고 어떻게 되찾았나), 그 말의 낱말과 빌려 온 곳.
- 지구본 지도 모드 **[지식]**(E1 에서 자리만 있던 "기술" 모드): 고른 발견을 아는 사람이 사는 칸을 밝게.
- 알림 · 팝업(E4 의 등급 규칙): ★★★ 세계에서 마지막으로 아는 사람이 죽음(그림이 남았는지 함께) · ★★ 한 무리에서 끊김 / 되찾음.

**6. E4 에서 넘어온 일**
- **구리가 아직 0/20** — 가르치기로 숯 · 돌 화덕을 아는 사람이 무리 안에 퍼지면 길이 짧아질 수 있다. 이 단계 뒤에 다시 재서 보고(억지 금지).
- **실험의 49% 가 "같은 헛수고"**, 사람 하루당 450µs(E3b 245) — 무리 안에서 "그건 이미 해 봤는데 안 됐다"를 나누면(가르치기 · 이야기로 단서 나누기) 헛수고가 줄어 계산도 줄 것. 줄었는지 재기.
- [넘기기] 끝 요약의 "죽음 0"과 사람 목록의 "죽음 3"이 어긋나 보임 → 같은 기준으로.
- "장면을 불러왔습니다" 알림이 위쪽 단추 글자와 겹침 → 겹치지 않게.
- **버그(사용자 보고): 지구본에서 사람이 다 떠나거나 죽은 칸에도 사람 표시(사람 모양 + 숫자)가 계속 남는다**(넘기기 뒤에 특히 잘 보임). 원인: `GlobeView.SetPeople` 에서 남는 표시판을 숨기기만 하고 칸 번호를 −1 로 지우지 않아, `UpdateMarkers` 가 칸 번호가 있는 표시판을 다시 보이게 한다. 고치고, "사람이 다 떠난 칸에는 표시가 없다"는 확인(테스트나 자동 확인 장면)을 넣기. 넘기기 전후로 지구본의 표시 · 열린 칸 · 화살표 · 언어 색이 지금 상태와 맞는지도 확인. 넘기기가 끝나면 넘기기 직전에 보던 화면(지구본 / 2D)만 다시 켜기(지금은 둘 다 켬 — `Main.UpdateSkip`).

**7. 측정** (만드는 중엔 시드 4개 · 짧게, 시드 20개 전체는 마지막에 한 번, 가능하면 시험용 장면 · 미리 돌린 세계에서 시작)
- 기획서 20절(옛 v2 수치): 정착지(무리)에서 **한 사람만 아는 법 ~17%** · 끊긴 것의 **~58% 를 되찾음(중앙값 3년)**.
- 끊김 · 되찾음 수(세계 · 무리), 되찾은 길(이웃 · 그림 · 다시 발견) 비율, 그림 수와 쓰인 횟수.
- 발견 목표 다시(모닥불 · 토기 · 돌 화덕 · 숯 · 구리) — E4 와 비교.
- 사람 하루당 비용 · 같은 헛수고 비율. 측정에 걸린 시간도 보고서에.

**8. 테스트** — 최소한:
- 같은 시드 → 같은 결과(지문) · 저장 → 불러오기 → 계속(배우는 중 · 잊는 중 · 그림 포함)
- 가르치면 배우는 사람의 아는 정도가 쌓이고, 말이 다르면 느림(알아듣기 % 에 따라)
- 안 쓰면 흐려지고 다시 쓰면 되살아남
- 아는 사람이 다 죽어도 그림이 있으면 그림을 본 사람이 되찾을 수 있음
