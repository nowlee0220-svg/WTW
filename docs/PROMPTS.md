# WTW — 단계별 프롬프트

> 사용법: 새 세션에서 **"docs/PROMPTS.md 의 [머리말]·[E0] 을 읽고 그대로 실행해줘"** 처럼 한 줄로 시킨다.
> 단계는 검토가 끝날 때마다 기획·검토 세션이 하나씩 추가한다. (지금 있는 단계: E0 ✅ · E1 ✅ · E2)

## [머리말] — 모든 단계 공통

너는 **WTW (Watch The World)** 의 한 단계를 구현하는 세션이다.

1. **시작 전에**
   - `git fetch origin main` 후 **`main` 의 최신**에서 작업 브랜치를 시작한다. (옛 버전에서 시작해 수정이 빠진 일이 있었다.)
   - `CLAUDE.md` · `docs/PLAN.md` · `docs/HISTORY.md` 8절을 읽는다. 이 프롬프트와 기획서가 다르면 **이 프롬프트가 우선**, 둘 다 애매하면 기획서의 원칙(3절)을 따른다.
   - 맡은 단계만 한다. 다른 단계의 일은 하지 않는다.
2. **하는 동안**
   - 결정론 규칙(`CLAUDE.md` 9번)을 지킨다.
   - 시뮬(`sim/`)은 Godot 를 모른다. 화면(`game/`)은 스냅샷을 읽기만 한다.
   - 결과를 억지로 유도하는 코드를 쓰지 않는다. 목표에 못 맞추면 그대로 적는다.
   - 기획서와 다르게 해야 하면 멋대로 바꾸지 말고 보고서의 "기획과 다르게 한 것 / 이유"에 적는다.
   - 빠른 테스트는 수 초~1분 안에 끝나게. 느린 테스트(긴 측정)는 따로 묶어 단계 끝에 한 번.
3. **끝낼 때**
   - 모든 빠른 테스트 통과 · 윈도우 실행 파일(zip) 빌드 성공 · 가상 화면 스크린샷으로 화면이 실제로 뜨는지 확인.
   - 보고서 `docs/reports/<단계>.md`:
     1. **쉬운 말 다섯 줄** (개발자가 아닌 사람이 읽는다)
     2. **해 볼 것** — 실행 파일을 받아 무엇을 눌러 보면 되는지 번호 목록
     3. 한 일 · 측정 결과(목표 대비) · 스크린샷
     4. 기획과 다르게 한 것 / 이유
     5. 알려진 문제 · 다음 단계에 넘길 것
   - 자기 브랜치에 커밋·푸시하고 **`main` 으로 가는 PR** 을 만든다. PR 본문 맨 앞에도 쉬운 말 다섯 줄.
   - 윈도우 zip 을 사용자에게 **파일로 보낸다**(파일 보내기 도구가 있으면 그것으로). 윈도우가 처음 실행 때 "PC 보호" 경고를 띄우면 "추가 정보 → 실행"으로 연다는 안내를 붙인다.
   - 사용자에게 하는 마지막 말은 **쉬운 한국어**로, 보고서의 다섯 줄 + 해 볼 것 + PR 링크.

## [E0] 바탕

### 목표
뒤의 모든 단계가 기댈 **뼈대**를 만든다. 행성·사람 같은 실제 내용은 넣지 않는다. 대신 두 가지를 먼저 증명한다:
1. **끊기지 않는 움직임** — 시뮬이 정한 일정을 화면이 매 프레임 부드럽게 따라간다(기획서 6절·17절).
2. **사용자 손에 도착하는 길** — 클라우드에서 만든 윈도우 실행 파일이 사용자에게 가서 실행된다.

### 만들 것

**1. 저장소 구성** (기획서 4절)
```
sim/            Wtw.Sim        — .NET 8 클래스 라이브러리, Godot 참조 없음
sim.tests/      Wtw.Sim.Tests  — xUnit. 빠른 테스트 / 느린 테스트(Trait 로 구분)
tools/bench/    Wtw.Bench      — 측정 도구(콘솔)
tools/*.sh      setup.sh · build.sh · export-windows.sh · screenshot.sh · test.sh
game/           Godot 4.5.1 .NET 프로젝트 (sim 을 프로젝트 참조)
data/           콘텐츠 JSON (지금은 견본만)
Wtw.sln
```

**2. 시뮬 코어 (`sim/`)**
- **결정론 난수**: 빠르고 품질 좋은 생성기(PCG32 나 xoshiro256** 등). 스트림 = (이름 × 지방 번호) 에서 안정 해시로 시드를 뽑는다. 상태를 저장/복원할 수 있어야 한다.
- **안정 해시**: 문자열·숫자 조합 → 64비트. 플랫폼·실행마다 같은 값(`string.GetHashCode` 금지).
- **시간**: 림월드식 틱 시계(기획서 6-1). 1시간 = 2,500틱 · 하루 = 60,000틱 · 1년 40일. 틱 ↔ "○년 ○일 ○시 ○분" 변환·표시 함수.
- **예약 계산기(스케줄러)**: "이 대상은 이 시각에 다시 계산" 을 예약하는 우선순위 큐. 같은 시각이면 **정해진 순서**(예약 순번)로. 예약 취소·당김(급한 일로 끊기) 지원. 하루 경계 훅(지방끼리 주고받기용 자리).
- **세계 껍데기**: 시드 · 시계 · 지방 목록(지금은 빈 것) · 엔티티 저장소(아이디 발급이 결정론적).
- **개입 기록**: 플레이어가 한 일(시각 + 종류 + 값)의 목록. **시작 기록 = 시드 + 설정 + 개입 기록** 이면 세계를 처음부터 똑같이 다시 만들 수 있어야 한다.
- **저장/불러오기**: 버전 번호가 붙은 파일. 저장 → 불러오기 → 계속한 결과가 끊김 없이 계속한 결과와 **비트 단위로 같다**.
- **데이터 읽기**: `data/*.json` 을 읽고 검사(아이디 중복 · 없는 아이디 참조 · 필수 칸)해서, 틀리면 어느 파일 몇 번째 항목이 왜 틀렸는지 쉬운 문장으로 알려 준다. 견본 데이터 두세 개(예: 재료 3개 — 기획서 8-1 의 속성 몇 개를 담아)로 시험. **진짜 데이터는 E4 에서** 만든다.
- **스냅샷**: 화면이 읽을 수 있는 "지금 상태"의 읽기 전용 사본. 시뮬 스레드가 만들고 화면 스레드가 가져간다(이중 버퍼 등, 잠금이 화면을 멈추지 않게).
- **움직임 시험용 대상**: "점" N 개가 지도 위 임의 지점 사이를 걷는다. 각 점은 "출발 시각 · 도착 시각 · 경로(꺾인 선)" 를 정하고 도착 시각에 다음 목적지를 예약한다. (E3 사람의 걷기가 이 구조를 그대로 쓴다.)

**3. Godot 껍데기 (`game/`)**
- 시뮬은 **별도 스레드**. 속도 단계는 기획서 6-2 의 표 그대로, 화면에는 **1배속 ~ 5배속**으로 표시: 일시정지 · 1~3배속(림월드 1배·3배·6배, 1배속 하루 약 16분 40초) · 4배속(하루 3초) · 5배속(하루 0.4초). 키보드: 스페이스 = 일시정지, 1~5 = 속도. (자동 속도는 E0 에서는 만들지 않는다 — 사건이 없으므로.)
- 화면은 스냅샷 + 일정(출발·도착 시각·경로)으로 **매 프레임 보간**해 점을 그린다. 점 500개, 60fps 목표. 시뮬이 바빠도 화면은 끊기지 않는다.
- 화면 위: 날짜(○년 ○일 ○시) · 속도 · 측정값(화면 fps · 시뮬 하루/초).
- 아래 메뉴 막대 자리(림월드식) — 버튼은 저장 · 불러오기 · 새로 시작 정도만.
- **한글 글꼴** 포함(나눔고딕이나 Noto Sans KR 등 OFL 글꼴, 라이선스 파일 같이). UI 테마 바탕(글자 크기 · 색 · 창 모양을 한 곳에서).
- 그림 공급을 한 곳으로 모은다(기획서 17절: 지금은 코드로 그린 원 · 나중에 갈아 끼움).
- 화면 크기: 1920×1080 기준, 창 크기를 바꿔도 깨지지 않게.

**4. 측정 도구 (`tools/bench`)**
- 헤드리스로 "점 N 개 × D 일" 을 돌려 **게임 하루/초**, 메모리, 한 번 계산당 평균 시간을 잰다.
- 결과를 JSON 으로 저장하고 **기준 파일**(`tools/bench/baseline.json`)과 비교해 빨라졌나/느려졌나를 한 줄로 보여 준다.
- 여러 시드를 코어마다 나눠 돌리는 옵션(뒤 단계의 "시드 20개 중앙값" 용).

**5. 테스트 (`sim.tests/`)** — 최소한:
- 같은 시드 → 같은 난수열 / 스트림이 서로 독립 / 새 스트림을 추가해도 기존 스트림 값이 안 바뀜
- 안정 해시가 알려진 값과 같음(값을 테스트에 박아 둠)
- 달력 변환(분 ↔ 년·일·시·분)
- 스케줄러: 같은 시각 순서가 정해져 있음, 취소·당김
- 저장 → 불러오기 → 계속 = 끊김 없이 계속 (비트 단위)
- 시작 기록으로 다시 만든 세계 = 원래 세계
- 데이터 검사가 틀린 데이터를 잡음
- 점이 도착 시각에 정확히 도착하고, 보간 위치가 경로 위에 있음

**6. 빌드와 전달**
- `tools/setup.sh`: 클라우드(우분투)에 .NET 8 SDK · Godot 4.5.1 .NET(리눅스, 헤드리스 실행용) · **윈도우 내보내기 템플릿**을 `.tools/` 에 설치. 이미 있으면 건너뜀. (옛 기록: 이 조합은 클라우드에서 된다고 확인됨.)
- `.claude/settings.json` 에 **SessionStart 훅**으로 `tools/setup.sh` 를 걸어, 뒤 세션들이 자동으로 환경을 갖추게.
- `tools/export-windows.sh`: 윈도우 x86_64 실행 파일을 내보내 `dist/WTW-<단계>-windows.zip` 으로 묶는다(실행에 필요한 .NET 파일 포함, 사용자 PC 에 따로 설치할 것이 없게).
- `tools/screenshot.sh`: 가상 화면(xvfb)에서 게임을 몇 초 돌리고 스크린샷.
- **GitHub Actions CI**: PR 마다 빌드 + 빠른 테스트. 가능하면 윈도우 zip 도 만들어 CI 결과물로 올린다(사용자가 GitHub 에서도 받을 수 있게).

**7. 보고서** `docs/reports/E0.md` ([머리말] 의 형식)

### 다 됐다는 기준
- [ ] 빠른 테스트 전부 통과, CI 초록
- [ ] 점 500개를 5배속으로 돌려도 화면 60fps 근처, 움직임이 뚝뚝 끊기지 않음(1배속에서 특히)
- [ ] 측정: 점 500개 헤드리스 **하루/초** 를 기록하고 기준 파일로 저장 (목표 수치는 없음 — 이 값이 앞으로의 기준)
- [ ] 저장 → 불러오기 → 계속이 같은 결과(테스트) + 게임 화면에서도 됨
- [ ] 한글이 깨지지 않음(스크린샷)
- [ ] 윈도우 zip 이 사용자에게 전달됨 + 해 볼 것 목록
- [ ] PR(→ `main`) 생성

### 해 볼 것 (사용자에게 줄 목록의 바탕)
1. zip 을 풀고 `WTW.exe` 실행 (경고가 뜨면 "추가 정보 → 실행")
2. 점들이 부드럽게 움직이는지 본다
3. 1~5 키로 1배속 ~ 5배속을 바꿔 본다, 스페이스로 멈춘다
4. 저장 → 조금 더 돌림 → 불러오기 → 점들이 저장한 자리로 돌아오는지
5. 위쪽 날짜가 "○년 ○일 ○시" 로 넘어가는지

## [E1] 행성

### 목표
**3D 지구본**으로 행성을 만들고 돌려 볼 수 있게 한다. 아직 사람·지방 지도는 없다(지방 지도는 E2). 기획서 5-1 · 5-2 · 5-5 를 따른다.
이 단계가 끝나면 사용자는 **새 세계를 만들고, 지구본을 돌리고, 칸을 눌러 어떤 땅인지 보고, 지도 모드를 바꿔 볼 수 있다.**

### 만들 것

**1. 측지 육각 격자 (`sim/`)**
- 정이십면체를 나눈 측지 격자(골드버그 다면체). 분할 수 72 → **전체 51,842 칸 = 육각형 51,830 + 오각형 12**.
- 칸마다: 아이디(0부터 차례, 결정론적) · 중심 좌표(단위 구) · 이웃 목록(시계 방향으로 정렬, 육각형 6 · 오각형 5) · 꼭짓점(화면용).
- 격자 자체는 시드와 무관하다 — 한 번 만들어 캐시해도 된다. 만드는 데 걸리는 시간을 측정해 보고.
- 결정론: 좌표를 실수로 계산하더라도 **칸 번호·이웃 순서는 정수 규칙으로** 정해서 기계마다 같게. 지형 생성에 쓰는 실수 계산이 기계마다 다르게 나올 수 있는 곳(삼각함수 등)은 결과를 정수 칸 값(고도 단계 등)으로 바꿔 저장하고, 시뮬은 그 정수만 쓴다.

**2. 행성 만들기**
- 설정(새 세계 화면에서 고름): **시드 · 땅의 양**(16,000 기본 / 20,000 / 24,000 — 같은 행성에서 땅 비율만 바뀜) · **기후 경향**(추움 / 보통 / 따뜻함).
- 땅 칸 수는 고른 값의 ±3% 안에 들어야 한다.
- 모양: **큰 대륙 하나(땅의 70~85%) + 작은 섬 3~8개.** 해안선은 들쭉날쭉하게, 산맥 · 고원 · 평야 · 호수.
- **오각형 12개는 바다에 오도록** 행성을 돌려 놓는다(또는 대륙 위치를 고른다). 땅에 걸리면 몇 개였는지 보고.
- **고도**: 정수 단계(예: 깊은 바다 · 얕은 바다 · 해안 · 평지 · 언덕 · 산 · 높은 산).
- **기후는 지역별 고정**(보이는 계절 없음): 위도 · 고도 · 바다와의 거리 · 바람(위도대별 탁월풍, 산맥 뒤 비그늘)로 **연평균 기온 · 강수량**.
- **생물군계**: 기온 × 강수로 — 얼음 · 툰드라 · 침엽수림 · 온대림 · 초원 · 사막 · 사바나 · 열대우림 · 습지 · 고산 등 10개 안팎.
- **강**: 높은 곳에서 바다·호수로 흐르는 칸 사이 선. 강이 있는 칸 표시.
- **땅속·땅위 자원**(칸 단위, 아직 개수 대신 "있음/많음"): 돌 · 부싯돌 · 진흙 · 구리 · 주석 · 철 · 소금 · 숲 · 사냥감 · 물고기 정도. 지형과 맞게(진흙은 강가, 구리는 언덕·산 …). **E4 의 재료 데이터가 이 이름을 그대로 쓸 수 있게** 아이디를 정해 `data/` 에 둔다.
- 칸마다 **지방 시드**(E2 에서 지방 지도를 만들 때 쓸 값)도 정해 둔다.
- 저장: 행성은 **시드 + 설정으로 다시 만들 수 있으므로 칸 하나하나를 저장하지 않는다.** 저장 파일엔 시드·설정만(+ 나중에 바뀐 칸만). 불러오기 = 다시 만들기 → 같은 행성(지문 테스트).
- 목표 시간: 행성 만들기 **10초 이내**(클라우드 측정값 보고).

**3. 지구본 화면 (`game/`)**
- 행성을 **하나의 메시**로 그린다(칸마다 노드를 만들지 말 것). 칸 색은 정점 색이나 텍스처로, 지도 모드를 바꾸면 색만 다시 칠한다. **60fps** 목표.
- 높낮이: 산은 살짝 솟게(과하지 않게), 바다는 매끈하게. 단순한 빛(해가 한쪽에서)으로 둥근 느낌.
- 조작: **왼쪽 끌기 = 돌리기**(관성 있게, 부드럽게), **휠 = 확대/축소**(부드럽게, 가까이 가면 칸 경계선이 보임), 칸 **누르기 = 고르기**(테두리 강조).
- **칸 정보 창**(오른쪽 또는 아래 한 칸, 기획서 7-6 의 "창끼리 가리지 않게"): 생물군계 · 고도 · 연평균 기온 · 강수 · 강/해안/호수 · 자원 · 좌표(위도·경도) · **왜**(예: "춥다 ← 북쪽 높은 위도 + 산 위", "비가 적다 ← 산맥 뒤 비그늘").
- **지도 모드**(아래 막대의 단추 + 키): 지형(기본) · 생물군계 · 기온 · 강수 · 자원(고른 자원이 있는 칸만 밝게). 세력·인구·교역·기술 모드는 **단추 자리만** 두고 "아직 없음"으로(E7~ 에서 채움). 모드마다 작은 **범례**.
- **새 세계 화면**: 게임을 켜면 먼저 나온다. 시드(직접 입력 / 무작위) · 땅의 양 · 기후 경향 → [만들기]. 만드는 동안 진행 표시.
- E0 의 점 시험 화면은 없애거나 개발용 키로만 남긴다(사용자에게는 지구본이 기본).
- 그리기 방식: E0 에서 고른 "호환(OpenGL)" 으로 지구본이 충분히 예쁘고 빠르면 그대로. 부족하면 바꾸고 이유를 보고서에.

**4. E0 검토에서 넘어온 작은 일**
- **저장 단추 = 멈춘 다음 저장.** 달리는 중에 저장하면 화면보다 앞선 상태가 저장되는 문제(E0 보고서 "알려진 문제") — 멈춰서 화면이 시뮬을 따라잡은 뒤 저장하면 "보이는 것 = 저장된 것".
- **CI 의 윈도우 zip 이름**이 `E0` 로 고정돼 있다 → 단계 이름을 한 곳(예: `game/project.godot` 의 version)에서 읽게.
- **측정 기준 비교**: 기준 파일은 그것을 잰 컴퓨터에서만 의미가 있다(클라우드 컴퓨터마다 ±40% 차이). 기준 파일에 컴퓨터 정보(코어 수 · CPU 이름)를 같이 적고, 다른 컴퓨터면 "느려짐" 대신 "다른 컴퓨터 — 비교 안 함"이라고 알려 주게. 같은 실행 안에서 **기준 코드와 새 코드를 번갈아 재는 방식**도 괜찮다.

**5. 테스트** — 최소한:
- 격자: 칸 51,842 · 오각형 12 · 모든 이웃 관계가 서로 맞음(A 의 이웃에 B 면 B 의 이웃에 A) · 이웃 수 5/6
- 같은 시드 + 설정 → 같은 행성(칸별 값 지문) · 다른 시드 → 다른 행성
- 땅 칸 수가 설정 ±3% · 큰 대륙 비율 70~85% · 섬 3~8개 (시드 20개에서)
- 오각형이 땅에 걸린 시드 수 보고
- 강은 높은 곳 → 낮은 곳으로만 흐르고 바다·호수에서 끝남
- 저장 → 불러오기 → 같은 행성

- [ ] 새 세계 화면 → 행성 만들기 10초 이내(클라우드) → 지구본

## [E2] 지방

### 목표
지구본의 땅 칸을 누르고 들어가면 **그 지방의 2D 지도**가 펼쳐진다. 아직 사람은 없다(E3). 기획서 5-3 · 5-4 · 10절(타일 하나에 오브젝트 하나) · 17절(그림은 코드로)을 따른다.
이 단계가 끝나면 사용자는 **땅 칸으로 들어가 숲·강·바위·광맥이 있는 지방을 둘러보고, 이웃 지방까지 이어 보고, 다시 지구본으로 나올 수 있다.**

### 만들 것

**1. 지방 지도 만들기 (`sim/`)**
- 지방 = 행성의 땅 칸 하나. 지도는 **150×150 네모 칸**이고, 그 안의 **육각형 모양만 쓰는 땅**, 바깥은 쓰지 않음(검게).
  - 육각형의 **여섯 변 = 행성 칸의 여섯 이웃**(E1 의 이웃 순서 = 시계 방향 그대로). 어느 변이 어느 이웃인지 정해 두고 그대로 쓴다.
  - **오각형 칸**(땅이 많을 때 몇 개 생김): 육각형 지도에서 **한 변을 막는다**(그 변은 절벽이나 바다처럼 넘을 수 없게). 이웃 다섯 개는 나머지 다섯 변에.
- **처음 들어갈 때** 칸 정보(지형 · 높이 · 생물군계 · 기온 · 강수 · 강 · 해안/호숫가 · 자원 단계) + `Planet.ProvinceSeed(칸)` 로 만든다. 같은 칸 = 언제나 같은 지도(결정론). 만든 지도는 기억해 두고, **저장 파일에는 지도 전체가 아니라 "바뀐 것"만**(지금은 늘 없음 — 나무를 베는 것 같은 변화는 E3~ 에서) 넣을 수 있는 자리를 만든다.
- 땅 칸(타일)마다: **땅 종류**(흙 · 풀밭 · 모래 · 진흙 · 바위 땅 · 눈 · 얕은 물 · 깊은 물 · 습지 …) + **높이 단계** + 그 위에 **오브젝트 최대 하나**.
- **이웃과 이어지게**: 변을 맞댄 두 지방은 경계에서 자연스럽게 이어져야 한다 — 강은 행성의 강 방향(`Downstream`, 위쪽에서 흘러드는 이웃)과 같은 변으로 들고 나고, 해안 쪽 변은 바다, 산 쪽 변은 높다. 경계의 모양은 **두 칸 번호로 정한 공유 시드**로 만들어, 어느 쪽을 먼저 만들든 같은 경계가 나오게.
- 강: 행성 칸의 강 크기(`RiverSize`)에 맞는 폭으로 지도를 가로지른다. 호숫가 · 해안 칸이면 지도 안에 호수 · 바다가 있다.
- 지형: 칸의 높이 단계에 맞게 — 평야는 대부분 평평, 언덕·산 칸은 바위 땅과 높낮이, 높은 산은 바위와 눈.

**2. 오브젝트** — "**타일 하나에 오브젝트 하나, 다루는 법에 따라 여러 자원**"(기획서 10절)
- 데이터 `data/objects.json`: 오브젝트마다 아이디 · 한국어 이름 · 어떤 생물군계/땅에 나나 · **다루는 법 → 나오는 자원** 목록.
  - 예: 사과나무 — 따기 → 사과 / 베기 → 나무 · 소나무 — 베기 → 나무, 송진 · 덤불 — 따기 → 열매 / 베기 → 잔가지 · 큰 바위 — 깨기 → 돌 · 부싯돌 무더기 — 줍기 → 부싯돌 · 구리 광맥 — 캐기 → 구리 광석 · 진흙 바닥 — 파기 → 진흙 · 갈대 — 베기 → 갈대 · 풀 — 베기 → 풀
  - 생물군계마다 다른 나무·풀(열대우림 · 온대림 · 침엽수림 · 사바나 · 사막 · 툰드라 …). 처음엔 20~30개면 충분.
  - 자원 아이디는 **E1 의 `data/resources.json` 과 같은 이름 체계**. 자원 아이템 자체(사과 · 나무 · 돌 …)의 성질(기획서 8-1 속성)은 **E4 에서** 채운다 — 지금은 아이디와 이름만.
- 칸의 자원 단계(없음/있음/많음)가 지도 안 오브젝트 수를 정한다(구리 "많음"이면 광맥이 더 많이). 숲 칸이면 나무가 빽빽하게.
- 테스트로 데이터 검사(없는 자원 아이디, 겹치는 아이디).

**3. 2D 지방 화면 (`game/`)**
- **들어가기**: 지구본에서 땅 칸을 고르고 칸 정보 창의 **[들어가기]** 를 누르거나 땅 칸을 **두 번 누르면** 2D 로. **나가기**: [지구본으로] 단추 또는 Esc → 들어갔던 칸을 보는 지구본으로 돌아온다.
- 카메라: 끌기 = 이동(E1 의 관성 규칙 그대로 — 멈춘 채 놓으면 서기), 휠 = 확대/축소(부드럽게). 가장 멀리 = 지방 전체가 한 화면, 가장 가까이 = 타일 하나가 화면에서 손가락만 하게(E3 에서 사람을 볼 크기).
- **선택한 곳만 밝게, 나머지는 검게**(기획서 5-4): 밝은 범위는 지금 들어간 지방. 위쪽 단추 **[이 지방만] / [이웃까지]** — "이웃까지"를 누르면 **육각형 지방들을 빈틈없이 이어 붙여** 둘레 이웃(바다가 아닌 칸)까지 밝게 보여 준다. (세력이 생기면 E7 에서 "세력 전체"로 바뀐다.) 밝은 범위 밖은 완전히 검게, 가장자리에 이웃 지방 이름이나 방향만 흐리게.
- 타일이나 오브젝트에 **마우스를 올리면 작은 카드**(이름 · 땅 종류 · 다루는 법 → 자원), **누르면** 같은 칸 정보 창에 자세히(지구본의 칸 정보 창과 같은 자리, 창끼리 가리지 않게).
- 그리기: 한 지방 = 22,500 타일 × (이어 보면 7 지방). **60fps** 를 지키는 방식으로(타일마다 노드 금지 — 한 번에 그리기). 프로그램을 키운 채 여러 지방을 드나들어도 느려지거나 메모리가 계속 늘지 않게.
- 지구본 칸 정보에 이 지방을 열어 봤는지 표시는 하지 않는다(기획서의 "흐릿함 → 열림"은 **사람이 들어가 사는 것**이 기준이라 E3 이후).

**4. 그림 (기획서 17절 — 사용자에게 그림 재료가 없다)**
- 땅과 오브젝트를 **코드로 그린다**: 해상도 높게(확대해도 각지지 않게), 림월드풍 단순 일러스트. 같은 종류도 시드로 조금씩 다르게(나무 크기·기울기·색).
- **타일 격자선이 보이지 않게**: 땅 종류의 경계는 부드럽게 섞는다(지구본에서 칸 선을 없앤 것과 같은 이유 — 보기에 불편함).
- 물은 잔잔하게 움직이는 느낌이면 좋다(과하지 않게, 성능 우선).
- 그림 공급은 E0 의 `Art` 한 곳으로 — 나중에 진짜 그림으로 갈아 끼울 수 있게.

**5. 측정**
- 지방 하나 만들기 시간(목표 **0.5초 이내**, 클라우드) · 지방 하나의 메모리 · 이웃까지 7 지방 만들기 시간.
- 빠른 테스트에는 작은 시드 몇 개, 느린 테스트로 **시드 20개 × 땅 칸 여러 종류**(평야 · 숲 · 산 · 해안 · 강 · 사막 · 툰드라 · 오각형)를 만들어 오브젝트 · 땅 종류 분포를 보고.

**6. 테스트** — 최소한:
- 같은 칸 = 같은 지도(지문), 다른 칸 = 다른 지도
- 육각형 밖 타일은 쓰지 않음 · 오각형 지방은 한 변이 막힘
- **경계가 맞음**: 이웃한 두 지방의 맞댄 변에서 강 · 바다 · 높이가 이어짐(어느 쪽을 먼저 만들어도 같음)
- 강이 행성의 강 방향과 같은 변으로 들고 남
- 칸의 자원 단계와 지도 안 오브젝트 수가 맞는 방향(많음 > 있음 > 없음)
- `data/objects.json` 검사
- 저장 → 불러오기 → 같은 지방(지도는 다시 만들어 같음)
