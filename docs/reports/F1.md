# F1 저장 고침 (결정론) — 보고서

## 쉬운 말 다섯 줄
1. **저장했다가 불러온 세계가, 저장하지 않고 계속 돌린 세계와 조금씩 달라지는 문제를 고쳤습니다.** 이제 저장 → 불러오기 → 계속해도 처음부터 이어 돌린 것과 한 치도 다르지 않습니다.
2. 원인은 E6(건물)에서 생긴 **"계산해 두고 다시 쓰는 기억" 두 가지가 저장되지 않은 것**이었습니다 — 움집 · 바람막이가 주는 따뜻함, 그리고 "고칠 만큼 낡은 건물 · 아직 묻지 못한 시신" 목록. 불러올 때 이것을 *불러온 시각*으로 새로 셈해, 하루 안에 사람 한 명이 다른 일을 고르고 그 뒤로 세계가 갈라졌습니다.
3. 그 둘을 저장 파일에 넣었고(저장 파일 버전 13 → 14), **옛 저장 파일(T1 판)도 그대로 불러옵니다.**
4. 다시 생기지 않게 **"세계를 갈래별로 견주는 도구"**를 만들고 시험에 넣었습니다 — 다음에 새 상태를 더하고 저장을 잊으면 "지방 21902 의 건물이 다르다"처럼 어디가 틀렸는지 바로 나옵니다.
5. **게임 결과는 하나도 바뀌지 않았습니다**(저장하지 않고 돌린 세계는 고치기 전과 사람 하나하나까지 같음). 계산 빠르기도 그대로(0.98~0.99배)입니다.

## 해 볼 것
1. zip 을 풀고 **`WTW.exe`** 를 실행합니다(윈도우가 "PC 보호" 경고를 띄우면 **"추가 정보 → 실행"**).
2. **[불러오기] → "50년 뒤 마을"** → **[넘기기] → 50년** 쯤 넘긴 뒤 **멈춤 → [저장]** → 몇 해 더 돌려 보고 → **[불러오기] → 빠른 저장** → 다시 계속. 문제없이 이어지는지(멈추거나 오류 창이 뜨지 않는지) 봐 주세요.
3. 지난 판(**T1 zip**)으로 저장해 둔 파일이 있다면, 그 파일을 새 판에서 **[불러오기]** 해 보세요. 그대로 열려 이어져야 합니다(옛 파일은 "따뜻함"만 불러온 때로 새로 셈하므로, 옛 판에서 이어 간 것과는 아주 조금 다를 수 있습니다 — 아래 "알려진 문제" 1).
4. **[불러오기] → "움집을 짓는 마을"** 을 2~3배속으로 며칠 돌린 뒤 저장 → 불러오기를 몇 번 해 보세요. 움집 · 바람막이가 그대로 있고, 사람들이 하던 일을 이어 가면 됩니다.

## 한 일

### 1. 재현
- `main`(T1, 4938698)에서 `SpeedSlowTests.ManyProvincesYearsOneEqualsFour` 가 실패하는 것을 확인했다(58초). CPU 1 과 4 는 같고, **불러온 세계만** 다르다.

### 2. 원인 찾기 — 갈래별 지문 (`SaveGame.Sections` · `SaveGame.DiffSections`)
- 저장 바이트를 **갈래**로 나눠 따로 해시한다: 세계 · 난수 흐름 · 세계 예약표 · 점 · 개입 기록 · 알림 · **지방마다**(바탕 · 예약표 · 짐승 · 밭 · 건물) · 발견 · 처음 잡은 짐승 · 사연 있는 물건 · 그림 · 넘겨주기 대기 · 말 · **사람마다** · 미룬 일. `DiffSections(a, b)` 는 다른 갈래의 이름을 낸다. 저장 코드에 "여기서부터 이 갈래"라는 표시만 단 것이라 저장 바이트는 그대로다.
- 3년 돌린 세계를 저장 → 불러온 **직후에는 모든 갈래가 같았다**(빠진 상태가 "저장 안 된 값"이 아니라 "저장 안 된 *기억*"이라는 뜻). 그래서 불러온 세계와 원래 세계를 나란히 조금씩 돌려 **처음 갈라지는 때**를 찾았다 → **불러온 뒤 0.88일, 지방 21902 · 사람 181 · 193 · 194**. 저장하지 않는 지방의 기억들(따뜻함 표 · 건물 바뀌는 때 · 땅의 사연 있는 물건 · 비 온 날 · 불 지킴이 …)을 하나씩 견주니 **지방 21902 의 따뜻함 표(Warm)** 가 달랐다.

### 3. 원인 — E6 의 "시각에 기대는 기억" 둘
| 기억 | 무엇 | 왜 갈라졌나 |
|---|---|---|
| **따뜻함 표**(`ProvinceLife.Warm`) | 타일마다 움집 · 바람막이가 주는 따뜻함. 건물이 바뀔 때만 다시 셈한다 | 셈할 때 그 순간의 낡음으로 "낡은 건물은 70%"를 정한다. 건물이 "낡음"(상태 400)에 닿은 뒤 다음 하루 경계(또는 다른 건물 일)까지는 아직 낡기 전 값을 쓰는데, 불러오면 **불러온 시각**의 낡음으로 다시 셈해 그 사이에 저장하면 표가 달라졌다 → 움집 안 사람이 느끼는 추위 → 쉴지 · 돌아다닐지가 바뀜. |
| **건물 모습**(`BuildView` 의 "낡은 건물" · "묻지 않은 시신") | 건물 일(고치기 · 묻기) 찾기에 쓰는 목록. 건물이 바뀔 때만 다시 만든다 | 낡은 건물은 만든 때의 낡음으로, 시신 목록은 만든 때의 시신 상태로 정해지고 다음 건물 변화까지 그대로 쓰인다(시신이 짐승에게 먹혀도 목록은 그대로). 불러오면 처음 쓸 때 새로 만들어 내용이 달라졌다. 따뜻함을 고친 뒤 같은 시험에서 **0.84일 뒤 사람 194 가 "쉼" 대신 "궁금해 돌아다님"**을 고른 것으로 찾았다. |
- 둘 다 E6 에서 새로 생겨 E5c(305ea1d) 에서는 통과, E6(9e8b2e3) 부터 실패한 것과 맞는다. E6 의 빠른 시험(건물 있는 세계 30일 + 6일)은 건물이 낡을 만큼 오래 돌지 않아 잡지 못했다.

### 4. 고친 것 (저장 파일 버전 14)
- **따뜻함**: 셈한 시각(`WarmAt`)을 깨어 있는 지방마다 저장하고, 불러올 때 **그 시각의 낡음으로** 다시 셈한다(`RestoreWarm`). 따뜻함은 (건물 + 셈한 시각)만으로 정해진다 — 다 지은 건물이 바뀌는 곳(다 지음 · 고침 · 무너짐 · 하루 경계의 낡음 · 깨어남)은 모두 다시 셈하므로.
- **건물 모습**: 맞는 모습이 있으면 그 "낡은 건물 · 묻지 않은 시신" 번호를 목록 차례 그대로 저장하고, 불러올 때 되살린다(`BuildViewForSave` · `RestoreBuildView`). 나머지(짓는 중 · 종류마다 · 수)는 건물만으로 정해지므로 다시 셈한다.
- **미룬 일 차례**(작은 것 — 결과에는 영향 없음, 저장 바이트만): 맞추는 시각(6분마다) 사이에 저장하면 불러온 세계는 "불러온 미룬 일 먼저, 그다음 지방마다"로, 원래 세계는 "지방마다"로 모아 써서 **다음 맞추는 시각까지 저장 바이트(지문)가 달랐다**. 적용하는 차례는 둘 다 (시각, 칸, 차례) 로 같아 결과는 같았다. 이제 **적용할 차례로** 써서 바이트도 같다.
- **옛 파일**: 버전 13 파일은 따뜻함을 불러온 시각으로 셈하고 건물 모습은 처음 쓸 때 만든다(고치기 전과 같은 길). 버전 1~12 도 전처럼 읽는다.

### 5. 다시 막기 — 새 시험

### 결과가 바뀌지 않았나
- 저장하지 않고 돌린 세계는 **고치기 전과 같다**: 고치기 전(`main`) · 고친 뒤 코드에서 같은 세계를 돌려 **형식과 상관없는 지문**(사람 하나하나의 저장 내용 전부 · 난수 흐름 · 처리한 예약 수 · 지방 예약표 · 건물 · 불 · 사연 있는 물건)을 견줬다 — "가족들 4곳 60일" · "50년 뒤 마을 + 10일" · "건물 세계 30일" · "300명 6년(CPU 4)" 모두 같음.
- **고정 지문 2개는 새 값으로**(`SpeedTests.PinnedFamilies` · `PinnedVillage`): 저장 파일에 버전 번호 · 따뜻함 시각 · 건물 모습이 더해져 *저장 바이트*가 바뀌었기 때문. 결과는 위처럼 같다.
- 300명 × 100년(아래)도 인구 · 죽음 · 태어남 · 예약 · 지방 넘기 · 깨어남이 고치기 전과 줄마다 같다(지문만 형식 때문에 다름).

## 알려진 문제 · 다음 단계에 넘길 것
1. **옛(T1 판, 버전 13) 저장 파일에서 이어 가면** 저장하지 않고 옛 판으로 이어 간 것과 아주 조금 다를 수 있다(따뜻함 · 건물 모습을 불러온 때로 새로 셈하는 길 — 고치기 전과 같은 동작). 파일은 잘 열리고, 거기서부터는 결정론이 지켜진다(같은 파일 → 같은 결과).
2. **시각 · 역사에 기대는 기억이 더 있을 수 있다.** 이번 시험들(300명 6년 · 장면 4개 × 24번 · E6 세계)에서는 갈라짐이 더 없었다. 앞으로 "건물이 바뀔 때만 다시 셈한다"는 기억을 만들 때는 그 안에 **시각(Now)이나 사람 상태**를 넣지 말 것 — 넣으면 저장하거나 다시 셈하게. E6 의 건물 모습은 `FarmView`("시각 · 사람 · 짐승에 따라 바뀌는 것은 넣지 않는다")와 달리 이 원칙을 어겼다.
3. **건물 모습의 시신 목록이 늦게 바뀐다**(결과에 남은 것, 고치지 않음): 시신이 짐승에게 먹히거나(Eaten) 해도 건물이 바뀌기 전까지는 목록에 남는다. 묻기 일을 고를 때 "죽은 지 닷새 안" 을 따로 보므로 큰 탈은 없지만, 위 2의 정리를 할 때 함께 볼 것.
4. 빠른 시험 `BuildTests.BuildingWorldDeterministic` 은 건물이 낡을 만큼 돌지 않는다 — 이번 `SaveRoundTripTests` 가 그 자리를 채운다.
5. (T1 에서 넘어온 것 그대로) 굶주림 · 들의 흉년 · 짐승이 열매를 먹음 → E6b.
